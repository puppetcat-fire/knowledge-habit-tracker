# 点亮 · 独立试作

这是按用户确认过的交互契约重做的可交互原型，**不是生产版本**。生产页面（仓库根目录的 `index.html` / `app.js` / `platform.*` / `server.js`）本轮没有改动；这里也不读写真实账号与事件记录，全部是模拟数据。

需求来源、冲突判定与目标流程见 [`docs/requirement-flow-review.md`](../../docs/requirement-flow-review.md)。

## 运行

```bash
npm run trial          # 静态服务，打开 http://127.0.0.1:3110/
npm run trial:test     # 域逻辑单测（34 项：计时/子任务/笔记/习惯/记录/候选/点亮/战报/方法版本）
npm run trial:check    # 真浏览器（headless Chrome）跑 42 项检查 + 截图 + 控制台错误
npx vitest run tests/trial-ui  # jsdom 里真跑 main.js 的集成测试（9 项，不需要 Chrome）
```

`trial:check` 需要本机有 Chrome/Edge，且在能创建命名管道的环境下运行（DSH 沙箱内 Chrome 会因 `mojo platform_channel` 报错退出，需要在非限制模式下执行）。截图输出在 `.checks/`（已 gitignore）。

想从头开始：打开 `http://127.0.0.1:3110/?reset=1`，或页面「个人主页 → 重置演示数据」。

## 本轮补上的契约缺口

- **节点归属**：公共节点属于全部点亮者、私人节点只属于个人，节点详情显示归属（示例里 `n-log`、`n-question` 是私人节点）。
- **方法贡献与版本**：节点详情可写新方法（默认仅自己可见），也可更新已有方法；更新会归档旧内容、版本号 +1，历史版本只读保留。过去实践记录固定当时的 `methodTitle + methodVersion`，方法以后怎么改都不改写历史。
- **免费/赞赏/抽成说明**：个人主页给出规则与示例账目（1,000 元订单 × 0.5% → 持有者池 2.5 元 + 平台 2.5 元），明确标注不是真实收入、未结算、不接支付。
- **达成后自愿支持**：有已养成习惯时在习惯页出现说明（完全免费、赞赏 2–5 元或推荐理念、不影响功能与推荐排序），不挡任何操作。
- **记录页的子任务**：标签显示「子任务·父事件名」，不再只有「子任务」两个字。

## 与旧原型的关系

`prototypes/interaction-review/`（16 屏可编辑原型 + 批注侧栏）保留不动，作为交互对照与批注来源。本试作把其中的页面与状态落成可运行实现：

| 旧原型屏 | 本试作 |
| --- | --- |
| `idle` / `running-read` / `running-stack` | 同一个计时页的待机与运行状态 |
| `choose` / `custom` | 事件选择下拉（搜索 + 自定义名称） |
| `report` | 结束战报弹层（不是独立页） |
| `habit` / `details-read` | 习惯页 / 习惯详情（侧边栏三级） |
| `records` / `details-write` | 事件记录页 / 事件详情（历史条目进入） |
| `knowledge` / `node` / `method` | 知识图谱 / 节点详情 / 方法折叠区 |
| `profile` | 个人主页 |
| `event-graph` | 不做成产品页；机制只写在说明里 |

## 明确没做的部分

真实登录与后端、真实支付与结算、真实概率学习算法、真实同步与多端、图片上传、管理端、完整日历复盘、推送通知、Android/Electron 客户端。这些在需求文档里保留，但在本试作里没有实现，也不会用模拟数据冒充完成。

## 已知取舍（待用户确认）

1. 养成判定按「同一周内的完成次数」计（一天做两次算两次），不要求五个不同日期。需求原文只说「每周五次」，旧模拟实现按不同日期，两者不一致，需要你确认。
2. 已养成习惯保留状态，不参与后续养成判定；是否要「保持者」机制未定。
3. 候选排序用可解释启发式（近期频率 / 同时段 / 最近顺序），真实算法未定。
4. 子任务结束时立刻勾选父事件对应步骤；是否要再确认一次未定。
