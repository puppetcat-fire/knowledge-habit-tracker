## 独立新模型接口

`action-state.cjs` 提供 `validateActionState` 与可安装的 `/api/action-state` GET/PUT 路由，使用独立 `dianliang-action-state/v1` 数据封装和独立目录。不会把原型数据送入旧 `/api/state` 再交给旧页面规范化。

数据按已认证账户保存。安装方必须提供可信服务端 `authenticate(req)`；测试中的 X-Test-Identity 只用于模拟账户断言，不能用作生产认证。当前没有将路由装进生产 server.js，也没有接正式会话或新前端。

接口保留全部允许的原型业务字段，不做名称、时间或版本转换。校验事件/习惯ID、活动源、活动段、单次笔记、步骤、父关系；明确支持时间戳0。历史/暂停/活动条目按原状态保存，时间段不重算，知识快照不丢弃。其他业务集合保留原样，**尚未进行完整知识、治理或公开资格校验**。

PUT必须携带GET返回的revision/ETag，通过修订比较再同步原子替换文件。现阶段仅单Node进程内同步处理的状态比较，不提供多进程锁或分布式事务保证。存储损坏返回错误并保留原文件；账户索引、密码、会话等不属于允许写入字段。

## 现有会话接入副本

`authenticated-app.cjs` 的 `createAuthenticatedActionApp` 复用现有注册、登录、me、退出及账户存储。新事件请求通过固定本机、当前监听端口的 `/api/me` 校验实际会话 cookie，避免复制密码校验或信任客户端账号ID。不是直接使用测试身份请求头。

默认数据目录为本独立 integration 下的 preview-data；可由测试显式指定临时目录。当前只提供应用工厂，没有启动常驻服务、接入OpenDesign页面或修改原server.js。它仍是服务接入副本，不是正式部署。

## 浏览器接入模块与防账号误写

`action-client.js` 可作为浏览器脚本或CommonJS模块使用，提供connect/save/readRemote/retryPending/snapshot/disconnect。调用方传入fetch传输；没有改动现有原型的同步save函数或挂载这些方法到页面。

完整状态快照串行保存，后一个使用前一个的返回修订标识。失败内容保存在账户上下文内存中；失败后后续队列停止发送，重试是显式操作。读取远端内容不会改掉当前编辑；带有未保存内容的重连也不自动刷新旧修订令牌，因此不会以重连为由覆盖冲突的新状态。

客户端随新状态请求发送X-Action-Account，服务仅将其用于与实际认证账户比较，绝不用它选择被读取/写入账户。浏览器会话已切换、但客户端仍持有旧账户内容时，返回ACTION_ACCOUNT_CHANGED；切换后新账户快照不暴露旧账户编辑。原账户再次连接可恢复本模块内存中原有未保存内容。
