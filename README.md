# 点亮习惯记录器

当前产品方向与完整推进路线见 [产品方向](docs/product-direction.md)。以用户指定的免费使用、自愿支持和教程产品外链分成为准。

本轮的可运行功能、启动方式、验收步骤与尚未完成的商业接入见 [交付说明](docs/product-delivery.md)。Windows 可双击本目录的 `start-product.cmd`；也可运行 `node server.js`。

一个为知识工作场景准备的习惯与事件记录网页，核心约束是：

- 用本机服务打开时先注册；习惯、计时、事件和点亮都留在这台机器的账号里
- 一次只养一个习惯，尽量减少注意力切换
- 重复事件会自然浮出为“节点候选”，为后续教程化、知识共建做准备

## 现在有什么

打开页面先注册或登录。名字和密码只写在这台机器的 `data/` 里。登录之后，习惯页负责计时和事件。知识平台是一棵树，点进节点能看到打卡：一段文字、一张图片，或两者都有。对着节点做完的一次计时也会记在那个节点上。退出在概览页。

- 单习惯养成：同一时间只维护一个激活习惯
- 下一段五分钟：知识平台根据所选目标、前置关系和确认点亮给出一个行动建议，直接交回原有计时流程
- 养成里程碑：连续四周、每周五次完成记录后，在原有习惯状态中给出自愿支持说明；继续免费使用
- 事件证据链：手动记录和计时记录都会沉淀为可追溯事件
- 本地种子树：页面直接读取仓库里的 `seed-trees/` 树数据，计时或手动记录可以挂靠到一个节点
- 知识共建共享平台：卡片流浏览节点，详情里展开方法，发出你自己的说法
- 自建知识树：从自己的目标建立路径，保留私人/公开边界，不限于数学种子树
- 个人主页：实践时间线、方法贡献、节点持有、可编辑介绍；本人私人记录与他人的公开主页分开呈现
- 方法贡献与历史：具体步骤、五分钟起步、资料/产品外链、不可变版本；实践关联当时方法
- 实测时间：今日与日/周/月汇总，手动记录不以预计时长冒充计时
- 明确分享：默认私人记录，主动公开或撤回；图片与文字采用同样的账户权限
- 本地点亮草稿：挂靠节点的那次记录会留下一条待发出的说法，由你确认（发出）后保留
- 节点候选：重复动作自动聚合，方便抽成教程节点
- 账号数据：通过本机服务使用时，习惯、事件和点亮保存在该账号下，仍只在这台机器，不会发到公网
- JSON 备份：原习惯备份继续保留；新增两个系统的完整账户导出和带预览的恢复，包括方法历史与实践图片
- 本机反馈接口：只有你主动启动本地服务时，反馈页才会写本机日志

## 快速开始

```bash
npm install
npm start
```

打开 [http://127.0.0.1:3000](http://127.0.0.1:3000)。

默认监听 `127.0.0.1`，只允许本机访问。

### 同域名社区验收

`npm run start:community` 在 `127.0.0.1:3105` 启动一个独立实例。习惯记录、知识平台和知识社区分别位于 `/`、`/knowledge/` 和 `/review/`。三处共用登录账号，习惯记录与社区预览各自保留行动档案。

通过 `PORT`、`HOST` 和 `DATA_DIR` 指定监听地址与数据目录。默认使用 `data/community-local`。审核员账号 ID 通过 `DIANLIANG_DISCUSSION_MODERATOR_IDS` 配置，多个 ID 用逗号分隔。验收时为每个运行实例使用独立数据目录。

## 桌面悬浮计时窗

如果你需要跨软件全局可见的计时器，用 Electron 桌面模式：

```bash
npm run desktop
```

桌面模式会打开两个窗口：

- 主窗口：完整习惯记录器
- 悬浮窗：始终置顶的计时窗

快捷键：

- `Ctrl+Shift+T`：显示或隐藏悬浮窗
- `Ctrl+Shift+H`：唤起主窗口

注意：

- 悬浮窗和 Electron 主窗口共享同一份本地状态
- 但它们和你平时用的 Chrome/Edge 浏览器不是同一个 `localStorage`
- 如果你之前已经在浏览器里积累了数据，先用网页版导出 JSON，再在 Electron 主窗口里导入

## 数据边界

### 永远本地的部分

- 激活习惯
- 历史习惯
- 事件记录
- 计时器状态
- 点亮草稿与已确认的点亮
- 备份导出文件

离线模式下，这些内容保存在当前浏览器 `localStorage` 与备份文件。通过本机服务登录后，习惯状态和记录会同步到该服务的账户数据目录；私人内容不会自动公开。请以实际运行的服务位置理解数据边界，不能把远端自托管服务当作纯浏览器本地存储。

### 离线分发要带上 `seed-trees/`

网页是从 `seed-trees/` 读取本地种子树的，离线分发（拷贝文件或 `file://` 直开）时必须一并带上 `seed-trees/`，否则森林功能区会整体隐藏，只保留一期的记录能力。

### 只有主动启用服务时才会写磁盘的部分

- 反馈页提交的问题日志
- 登录账户的习惯状态、节点、教程、实践和图片

它们写入服务端 `data/bug-reports.jsonl`，默认也只在本机可见。

## 开发检查

```bash
npm run lint
npm run typecheck
npm test
```

也可直接运行 `node scripts/check.js` 一次完成全部检查，不需要 npm 命令入口。

如果本机 Vitest 配置打包受到目录权限限制，可运行 `node node_modules/vitest/vitest.mjs run --configLoader native`。

运行 `npm run test:community` 可以单独验收社区的发布、讨论、关注、收藏、审核和账号隔离流程。

## 自托管与部署

两个界面共享账户服务；当前文件存储要求单进程访问同一数据目录。默认仅监听本机。完整启动、代理配置和部署边界见 [交付说明](docs/product-delivery.md)。数据目录不得暴露为静态目录，上云前应保存完整账户备份并配置 HTTPS、明确服务链接和运营审核。当前没有执行公网发布。
