# 点亮：OpenDesign 原型试作需求

整理日期：2026-10-07。本文提供给不继承聊天历史的子智能体。目标是使用 OpenDesign 做独立、可交互、可审阅的产品原型，供用户比较和修改；不是直接替换生产产品。

## 1. 权威与边界

用户明确要求：「如果不是有设计上的冲突，不要简化版本，不要随便改我设计。」不得为了美化、套模板或节省工作量删除功能、改变流程。本文的最新确认优先于旧说明文件；发现实际设计冲突须指出，不能偷偷替用户决定。

- 原始 PRD：`C:\Users\xiaob\Documents\时间管理计划书\时间管理APP-PRD需求文档.docx`。这是用户确认的初版，应读取以核对未在本文展开的原始条目。
- 当前已逐轮批注的原型：`prototypes/interaction-review/project.json`、同目录 `index.html`。必须读取，保留现有文件和用户修改；当前页面名称、功能与跳转是交互参考，粗糙的框线外观不是新视觉必须照搬的样式。
- 辅助背景：`docs/product-direction.md`、`docs/original-prd-alignment.md`、`docs/knowledge-tree-phase2-design.md`。旧文件中的上下预测按钮、手动事件关系、习惯与记录合页等内容，已被用户后续批注修正，不能重新引入。
- 新版本放独立 OpenDesign 项目以及本仓库 `prototypes/open-design-trial/`。不修改已有原型、生产文件、真实账户、后端和用户真实事件记录。
- 所有演示数据明确为模拟。没有实现的同步、付款、概率推断、分享和结算，不可冒充真实完成。

## 2. 产品与价值

产品暂名「点亮」。它是面向 INTP 等需要行动脚手架的人，提供习惯养成、事件记录、知识共创共享的基础设施。用户只需记录「我在做什么」「我做完了什么」，尽量减少额外的注意力消耗，却获得时间管理和实践积累的收益。

核心数据联系：「一个人，用了什么知识，做了一件什么事」。从用户想做的事和知识路径推荐下一段五分钟可以做什么。五分钟是起步建议，不把完整目标擅自改为五分钟任务；建议十五分钟的习惯使用正向计时，不到点强制停止。

希望帮助处于焦虑或抑郁状态的人建立时间消耗感知、降低行动门槛。原型不要添加诊断、治疗和疗效承诺，也不要用惩罚或羞耻提示驱动坚持。

## 3. 两系统、账号与导航

习惯记录与知识共创共享是两套完整的业务系统。用户只有一个域名，使用统一外壳和多级侧边栏承载；不要求用户在多个端口或网站之间跳转。

至少覆盖：

- 账号：名字、密码注册与登录；注册后进入记录主界面；具备账号主界面和个人主页。
- 习惯记录 → 计时、习惯、事件记录。
- 习惯记录 → 习惯 → 习惯详情（三级目录，支持展开、收起和进入当前习惯详情）。习惯页正文不再放重复的「查看习惯详情」「回到计时」按钮。
- 知识平台 → 知识图谱，以及选中节点后的详情、方法/教程与实践入口。
- 我的空间 → 个人主页，展示个人实践与知识足迹及账户入口。

计时页面不要把「习惯与记录」「知识平台」「我的空间」又堆成正文按钮，也不要重复显示产品名。侧边栏处理跨系统导航。编辑器的页面列表、保存文件、导出等属于原型工具，不能混进正式产品页面。

## 4. 计时和多级切换：最关键的状态规则

可以有无上限的未结束事件列表，但同一时间只能实际做一件事，因此只能有一个活动计时器。不是多条并行计时，也不是结束父事件就结束所有子事件。

例如：开始吃东西 → 开始喝水 → 开始打游戏。开始另一件事会暂停前一件的实际时间累计，前一件保留为未结束；可以切回任意未结束事件继续累计。每条记录有自己的 ID、开始时间、活动时间段和累计实际用时。

- 「切回」暂停当前活动事件并恢复所选未结束事件。暂停期间不累计时间。
- 结束任意一条只结束该条，不影响其他未结束条目。结束暂停中的吃东西，正在跑的打游戏继续。
- 结束活动事件后，不自动替用户恢复某个暂停事件；由用户决定下一件。
- 已结束事件立刻移出当前未结束列表，进入历史；不要保留「已结束 / 再开始」行占用注意力。再次做同名事情是新事件 ID。
- 活动条目和暂停条目的状态、计时、切回、结束必须清楚；切换不丢笔记。
- 没有活动事件时，事件选择区域展示最可能的事，并能快速点选、搜索或输入要做的事；不要只显示「当前没有正在计时的事」。
- 「开始计时」一键开始所选候选。候选按可能性排序，首项最可能；没有证据时不能显示虚构概率。
- 保留一个事件下拉选择入口，支持搜索。不要重新添加已删除的顶部事件标题和独立小箭头，也不要恢复「上一个预测事件 / 下一个预测事件」按钮。
- 正在计时时，下拉调整当前记录的事件名称是纠正本条事件，不应悄悄结束、重置或创建新记录；开始另一件事与修正本条应在交互上可区分。

刷新后原型状态应能恢复，不能出现多个计时器同时累计。长期任务列表可滚动，不用人为设置可记录数量上限。

## 5. 重复笔记、步骤与单次笔记

笔记始终跟目前实际正在跑的事一致。切回或开始不同事件时，相应内容随活动事件切换，不把其他事件笔记混进来。

### 重复笔记与步骤

重复笔记是这类事情每次复用的说明、步骤、提醒，既可写文字，也可添加逐项步骤；不局限于唯一正在养成的习惯。当前原型按事件名称保存复用模板，任务实例分别保存完成勾选。

- 步骤可新增、编辑、移除，依次勾选。
- 起床示例包含喝水、刷牙。新一次起床使用相同模板，但勾选状态重新开始。
- 步骤可「开始子任务」：父事件暂停并保留，子任务成为唯一活动事件；子任务有自己的计时和笔记。
- 已有对应未结束子任务则切回它，不无意复制。
- 子任务结束可将其父实例对应步骤标记完成，但不自动恢复或结束父事件。
- 自定义复用步骤不等于提供一般事件概率关系的手动编辑器。

### 单次笔记

单次笔记跟着具体事件 ID 走，不能跟习惯定义或事件名称共享。同名事件的新一次记录不会继承旧单次笔记。

- 显式保存按钮。
- 保存形成一条本次笔记，清空输入草稿，进入默认折叠的已保存笔记栏；支持继续保存多条，展开查看。
- 切换未结束事件保留各自草稿、保存条目。
- 结束后在历史事件及该事件详情中可查看；不能因为结束或切习惯丢失。

## 6. 结束战报

结束事件时弹出类似游戏战报的结果面板。视觉有完成感，但内容使用真实模拟操作产生的数据：事件名、实际累计时长、活动时间段、步骤完成情况、本次笔记，以及关联知识实践。

不添加编造的得分、等级、排名、连胜和奖励。未填写的笔记不补造。可完成关闭、查看事件记录；其他活动事件不被战报打断。待机、运行、战报是状态，不是需要长期导航的三个独立产品页面。

## 7. 习惯系统

「习惯」和「事件记录」是两页，不再合页。

- 同时只能养成一个习惯，可以切换。多个定义可以保留，但其他未养成习惯显示暂停养成；已养成习惯保留已养成状态。
- 新建习惯后作为当前唯一养成目标；原习惯和进度、记录保留。
- 修改名称不丢失习惯 ID 和历史。
- 切换养成目标本身不自动开始、结束或切换实际计时事件。
- 从当前习惯开始：有对应未结束记录时继续它，否则创建关联该习惯的新事件。
- 查看当前进度、已养成的习惯和过去实践；已养成习惯可展开详情，不能只展示当前一个。
- 习惯详情从侧边栏三级目录进入，显示重复说明、步骤定义、养成进度和关联实践历史。
- 事件记录详情只描述某一次事件的活动时间段、实际时长、步骤状态和单次笔记。入口在历史记录条目中；不能把它冒充习惯详情。
- 查看其他习惯或历史详情不暗中改变养成目标或实际计时状态。

养成业务口径是「同一习惯连续四周，每周坚持五次」。用户原文是次数，不得未经确认加上五个不同日期的限制；旧模拟实现若按日期算，标为待核对而非将其写成新需求。

## 8. 历史记录与概率关系

记录页覆盖所有事件，包括自由事件、习惯实践、子任务。支持今日、指定日、周、月、全部等范围，显示真实操作产生的用时和日期；折叠展开笔记与详情。

事件的多级关系、顺序或父子关系，是记录后内置的概率连接，主要服务于预测。用户不手动调整一般关系，只记录正在做和做完了什么。不要给用户添加「编辑事件图」「父子关系待你确定」或计时正文的「查看事件图」入口。机制说明可保留在原型说明中，但不能当作正式产品页。

显式开始某一步子任务与一般历史关系推断是两件事。原型演示不宣称已完成真实学习算法。

## 9. 知识共创共享系统

知识平台是完整服务，不是计时页旁边几个装饰按钮。知识图谱要体现人类知识与实践结晶的规模和关联感；用户明确不满意原有丑陋的树。应有可探索的整体结构、层级、领域和个人点亮足迹，同时避免靠随机发光圆点营造虚假内容规模。

- 节点描述目标，教程/方法描述怎么做，方法默认折叠、按需展开。
- 前置/后置推荐关系，与实例/原理关系区分；允许自由选择与跳关。
- 能选择目标与方法，看到下一段五分钟行动建议，进入计时实践。
- 记录使用的知识节点、教程及其当时版本、实践事件、时间、结果和证据；教程后续更新不改变过去使用过的版本。
- 完成事件形成点亮草稿，用户自证/确认；计时结束不能自动冒充目标已掌握。
- 贡献教程和版本、私有节点、公开共享与个人实践足迹可审阅。公开发布由用户主动选择，不默认把私人记录公开。
- 公共节点属于全部点亮者，私人节点属于个人，不把作者或维护者作为公共节点唯一持有者。
- 长期治理、群体持有与共创机制依据已有详细文件保留，不能因本次视觉试作删掉；未确定的具体分配算法不得捏造。

## 10. 免费、赞赏与收益

完整免费使用。养成后可自愿赞赏 2–5 元，或优先推荐产品及公司理念给别人；不作为收费门槛、不弹强制付费墙。

教程中需要的产品外链可以抽成，用户举例约 0.5%，抽成的一半分给对应节点持有者。公共节点归全部点亮者、私人节点归个人。公共持有者内部权重、归因、退款、结算等细节尚待确认，不擅自决定平均分或贡献权重。试作可说明规则、示例账目，但不接真实支付、不伪造收入或已结算状态，也不以抽成影响推荐排序。

## 11. 本次交付与验收

使用 OpenDesign 的产品界面设计能力，优先其 `frontend-design` 技能，通过 OpenDesign 的生成流程执行，不仅复制一个通用模板。清楚表达：安静、低注意力的行动记录；具有知识与实践积累感的知识平台。保持统一的设计系统和多级导航。

交付完整页面和关键状态、工作跳转、实际可操作的模拟计时/切换/步骤/笔记/习惯/记录闭环，及知识探索到实践和个人主页链路。不得将页面裁成只剩计时首页。

验收至少实际操作：

1. 开始吃东西，开始喝水，再开始打游戏；确认只能一个累积，切回、独立结束、结束后进入历史。
2. 起床步骤开喝水子任务，验证父事件暂停、子任务笔记独立、结束勾选且无自动恢复。
3. 保存单次笔记后折叠，同名新事件不继承；切换后重复笔记正确对应。
4. 新建和切换习惯时只一个养成中，历史保留；侧边栏三级习惯详情与事件详情入口正确。
5. 结束战报、历史日期筛选、节点方法进入实践、点亮确认、个人主页可到达。
6. 重载后模拟状态保留，桌面与窄屏可用，截图和浏览器错误检查。

未交付条目须逐项记录为未完成，不能以「简化版」「后续再补」替代本次要求。遇到真实矛盾或执行障碍，向主智能体汇报事实。
