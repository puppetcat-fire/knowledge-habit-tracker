# 产品方向与实现约束

依据：用户于 2026-09-30 在本项目明确提出的设想。本文覆盖旧方案中与本次设想冲突的收费、持有权和产品定位；其他已有设计继续保留。分阶段实现不等于删减最终设计。

## 产品要解决什么

为 INTP 等需要行动脚手架的人提供习惯养成、事件记录和知识共创共享平台。尽量减少为了管理时间而额外消耗的注意力，让用户知道时间用在了哪里，并能从想做的事情得到下一段五分钟的行动建议。

核心记录是「一个人，使用什么知识，做了一件什么事」。事件、来源节点、所用教程/版本、时间、实践结果与证据需要能连接起来。下一步建议由用户目标、知识路径和实践记录产生；不以延长浏览时间为目标。

帮助用户建立时间消耗的感知属于产品目标。用户也希望其能在一定程度上帮助焦虑、抑郁状态下的人开始行动。当前实现不提供治疗、诊断或疗效承诺。低负担、可暂停、自主选择、不中断操作是交互约束。

## 必须保留的已有设计

- 习惯记录与知识平台分别运行，保留现有视觉设计与二维知识树。
- 一次只养一个激活习惯；自由事件与非习惯行动仍能记录。
- 节点描述目标，教程描述方法；教程默认折叠。
- 节点完整目标以 5–15 分钟实践单元组织。五分钟建议是进入该目标的行动时段，不能自动把目标改写为五分钟，也不能以计时结束代替自证。
- 前置/后置是推荐关系，实例/原理是另一类关系；保留跳关与自由选择。
- 保留事件关联、点亮草稿/确认、私人节点、现有账号与保存重试机制。
- 私人记录与公开分享由用户选择；不会把所有事件自动发布。

## 用户明确指定的收费与归属

1. 产品免费使用。
2. 同一个习惯连续四周，每周坚持至少五次后，可以自愿赞赏 2–5 元；优先邀请用户把产品及公司理念推荐给其他人。达成不会变成付费门槛。
3. 知识平台的收入来源是教程需要用到的产品外链所产生的抽成，用户举例约 0.5%。这是候选费率，不当作已签订的商业渠道费率。
4. 抽成收入的一半分给对应节点的持有者，另一半归平台。例如有效订单金额 1,000 元、抽成率 0.5% 时，抽成 5 元，节点持有者池与平台各 2.5 元。此处是规则示例，当前没有真实支付或结算。
5. 公共节点归属于全部点亮者；私人节点归属于个人。不得把公共节点据为私人所有，或把公共持有者缩成只有作者/维护者。
6. 收费不改变知识目标的推荐次序，不把付费解锁节点、订阅或强制赞赏当作默认模式。

仍需决定的结算细节：公共持有者池内部的分配权重、有效点亮口径、订单归因窗口、多节点归因、退款冲销、费率基数与金额舍入。实现真实结算前需让这些规则具体可审查，当前不擅自采用平均分配或贡献加权。

## 2026-09-30 这一轮已经实现

- 以原项目最新提交 `f8b4c2a` 和原目录当时的未提交修改为基线，工作分支 `codex/product-continuation`。
- 知识树上方增加一个下一段五分钟建议，复用现有「看看目标」与「去做」流程。选中目标有缺失前置时优先给前置；否则沿最近确认的点亮继续，再选择可开始的未点亮目标。
- 建议只使用当前用户在当前树的确认点亮；草稿与其他树的记录不能当成完成。实例关系不会被当作强制前置。
- 保留完整目标和建议时长，不自动确认点亮，也不覆盖用户已经输入的动作。
- 在原有习惯周状态里判断连续四周、每周五次，达成后显示自愿支持说明。按本地周一至周日统计实际完成事件，排除随手记、未来记录、其他习惯和重复事件 ID；没有额外要求分布在五个不同日期。已经达成的历史四周不会因进入新一周而失去资格。
- 自建知识树与个人节点：不再只能使用数学示例；区分公开展示和私人可见性，私人树的边界覆盖内部节点。
- 教程贡献与版本：具体方法、前五分钟起步、资料/产品外链和关联标记；私人保存为默认，发布需主动选择，更新保留历史内容哈希，陈旧编辑返回冲突。
- 实践来源：选择方法后交回习惯系统，开始计时固定目标和教程快照，结束产生事件及点亮草稿。过去的事件与方法快照不会随教程更新而改变；知识节点可查看当时方法。
- 时间感知：今日、日/周/月记录显示实际计时时间；手动事件没有计时就明确不计时，不拿预计时长冒充实际耗时。本次日志与暂停状态可在刷新后恢复。
- 分享边界：实践默认私人，文字与图片均遵循账户权限；自证与公开是明确操作，可撤回分享而保留自己的记录。公共节点持有者接口按公开自证记录去重，私人节点归个人。
- 两系统完整备份：账户状态、自己的树/节点/连接、教程历史、实践与图片一起导出；恢复前显示内容数量，恢复为私人。服务端恢复有可重放事务，离线恢复有多键中断回滚；不覆盖其他账户内容。
- 安全与保存：账户同步冲突保留未保存内容，重试与导出入口继续存在；会话过期、登录限流、同源检查、图片鉴权和损坏文件停止写入。
- 佣金账本：运营侧本地记账，订单幂等、节点持有者快照、半数收益池、退款冲销和哈希链校验；金额保留精确分数，不擅自规定共同持有者的分配权重。没有实际收款或分账。
- Windows 启动入口 `start-product.cmd`；统一检查命令 `node scripts/check.js`。本次工作在独立工作树，原目录保持原样。

## 后续完整推进路线

1. 行动闭环：已关联目标、教程版本与实践；继续补齐长期路径发布、卡点/中止反馈和机证判题，保留自由选择与跳关。
2. 共创共享：已接通本机同服务账户之间的贡献、公开/撤回、证据可见性与持有查询；继续落实既有转群体持有、提案投票、分裂/合并、分布式内容交换与治理设计。
3. 自愿支持：确认产品与公司的理念文案，提供分享入口和实际赞赏渠道，保留免费的完整使用能力。
4. 产品外链与记账：已支持教程材料、外链标记和可追溯账本；继续接入真实渠道回执、订单归因窗口、多节点归因和签名校验，再按用户确认的分配规则结算。
5. 真实结算与分发：在渠道与结算规则确定后接入分账，继续推进桌面悬浮与 Android 端，而非用网页取代已有客户端。
