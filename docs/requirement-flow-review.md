# 点亮 · 需求流程梳理与重做基线

整理日期：2026-11-03。用途：在重新实现之前，把「需求从哪来、哪些被推翻、哪些还没定」摊开，给出可执行的目标流程与验收口径。本文不新增用户没提过的需求；凡是本文自行判断的地方都标为「本次判定」，凡是用户没定的标为「待确认」。

## 一、为什么要重做

现有仓库 `app.js`（85KB）+ `platform.js`（52KB）+ `server.js`（36KB）是一期与二期的实现，页面结构是四页 + 独立平台页；而用户后来用 16 屏可编辑原型逐轮批注出了另一套更完整的交互（统一外壳 + 多级侧边栏、单活动计时 + 未结束列表、重复笔记/步骤、习惯与记录分页、知识图谱、个人主页、战报）。两套东西同时在，导致：

1. **流程断层**：生产页面仍是「计时 / 概览 / 习惯与事件 / 反馈」四页，用户确认的多级侧边栏只在原型里存在。
2. **需求散落**：PRD、批注、方向文档、原型 notes、Codex 实现四份来源互相覆盖，没有一张表说明谁废了谁。
3. **没有可点的完整闭包**：原型能点但数据是硬编码的页面态；生产能跑但不是用户确认的流程。

所以本轮的交付不是「给旧页面上色」，而是按确认过的契约重做一个可运行、可审阅、刷新不丢状态的独立原型。

## 四、目标信息架构

只分三类：**页面**（有路由）、**状态**（同页变化，不是导航）、**弹层**（临时覆盖）。

```text
登录 / 注册（未登录时唯一入口）
└─ 统一外壳：多级侧边栏（可收缩为时钟）+ 工作区

习惯记录
├─ 计时            #/habit-record/timer
├─ 习惯            #/habit-record/habits
│  └─ 习惯详情      #/habit-record/habits/:habitId      （三级）
└─ 事件记录        #/habit-record/records
   └─ 事件详情      #/habit-record/records/:eventId      （三级，从历史条目进入）

知识平台
├─ 知识图谱        #/knowledge/atlas
│  └─ 节点详情      #/knowledge/atlas/:nodeId
│     └─ 方法展开   节点详情内的折叠区（可深链 #/knowledge/atlas/:nodeId/method/:methodId）

我的空间
└─ 个人主页        #/profile
```

**状态（不是页面）**：计时·待机、计时·运行中、计时·多级切换、事件下拉展开、战报弹层、单次笔记保存后折叠、候选展开、方法展开。
**明确不做成导航**：待机/运行/战报、事件关系图、编辑器工具（页面列表/保存/导出）。

侧边栏层级（需求书 §3 原话落实）：一级「习惯记录 / 知识平台 / 我的空间」；「习惯记录」下二级「计时 / 习惯 / 事件记录」；「习惯」可展开三级「当前习惯详情 / 已养成习惯详情」；一级收起时其下各级随之隐藏。

## 五、状态机

### 5.1 事件记录（核心，最易写错）

```text
创建(idle→running)：name + 开始时间，segments=[{start: now, end: null}]，活动
暂停（被切走）：当前 segment 闭合，endedAt 仍为 null
切回：目标 segment 重新打开，其他活动条目先暂停
结束（任意条目）：闭合当前 segment，写 endedAt，移出未结束列表 → 历史
不变式：同一时刻最多一条活动计时；segments 互不重叠；累计时长 = Σ(end-start)
结束活动条目后：不自动恢复任何暂停条目，不自动开始下一件
```

### 5.2 子任务

```text
开始子任务：父条目暂停 → 新建子条目(parentId, parentStepId) → 子条目成为唯一活动
子任务已有未结束实例：切回它，不重复创建
结束子任务：标记父实例对应步骤完成；不自动恢复父条目、不连带结束父条目
```

### 5.3 习惯

```text
定义（多条）→ 当前养成中（唯一一条）/ 暂停养成（其他未养成）/ 已养成（保留）
切换养成目标：只改"当前"，不自动开始/结束/切换任何计时事件
新建：生成独立 habitId，成为当前；旧习惯进度与记录保留
改名：保持 habitId
养成判定：同一习惯连续 4 个本地周、每周 ≥5 次已完成事件（按次数，不额外要求 5 个不同日期）
```

### 5.4 知识实践

```text
选择节点/方法 → 进入计时（固定节点 + 方法版本快照）
结束 → 形成实践事件 + 点亮草稿（draft）
点亮草稿 → 用户显式确认 → confirmed（自证），可撤回分享但保留记录
公开/私人：默认私人，公开是显式操作
```

## 六、数据模型（原型内模拟，存 localStorage）

```text
account   { id, name, createdAt }
habits    [{ id, name, createdAt, formedAt|null, state:'active'|'paused'|'formed' }]
events    [{ id, name, habitId|null, startedAt, endedAt|null,
             segments:[{ startedAt, endedAt|null }],
             notes:[{ id, text, at }], draftNote,      // 单次笔记：按事件 id
             parentId|null, parentStepId|null,
             stepDone:[stepId],                       // 本次实例的勾选
             knowledge:{ treeId, nodeId, methodId, methodVersion, snapshot } | null }]
stepTemplates { [事件名称]: [{ id, text }] }          // 重复笔记/步骤：按事件名称复用
knowledge { trees:[{ id, title, nodes:[{ id, name, goal, estMinutes, area, prereqs:[nodeId], examples:[nodeId] }],
                     methods:[{ id, nodeId, title, version, firstFive, steps:[{id,text,link?}], visibility, updatedAt }] }] }
lightups  [{ id, nodeId, methodId|null, eventId|null, at, state:'draft'|'confirmed', visibility:'private'|'public' }]
ui        { route, sidebarCollapsed, collapsedGroups, filters }
```

说明：`stepTemplates` 用事件名称做键是当前原型的做法（批注确认）；同名事件的重复笔记共享模板，单次笔记绝不共享。教程版本用 `methodVersion` 快照固定，方法后续更新不改历史事件指向。

## 七、关键规则（实现与测试都要覆盖）

1. 同一时刻只有一个活动计时；未结束条目数量不设上限。
2. 开始另一件事 = 暂停当前，不清空、不结束、不丢笔记草稿。
3. 结束任意条目只结束它自己；结束活动条目后不替用户选下一件。
4. 已结束条目立即离开未结束列表，进入历史；同名再开始是新事件 id。
5. 单次笔记按事件 id 归属：显式保存成条、清空草稿、折叠展示；同名新事件不继承。
6. 重复笔记/步骤按事件名称复用；勾选状态按事件实例保存，新一次重新开始。
7. 笔记内容始终跟随"当前活动事件"；查看别的记录不改当前笔记。
8. 候选：无活动事件时展示最可能的一件 + 一键开始；排序可用启发式（近期频率、时段、最近顺序），界面不显示概率数字。
9. 事件下拉支持搜索；改当前记录名称是纠正本条，不新建记录。
10. 习惯与记录分页；同时只有一个养成中；切换不改计时状态。
11. 战报只用真实数据（累计时长、活动时间段、步骤完成、本次笔记、关联知识实践），无编造项。
12. 点亮为自证，计时结束不自动确认；公开发布默认关闭。
13. 刷新后状态恢复，且不会出现两条活动计时（恢复时做一次归一化）。
14. 桌面与窄屏均可操作；键盘可达（焦点、跳过导航）；尊重减少动态效果。

## 九、验收用例（逐条可执行）

1. 开始「吃东西」→ 开始「喝水」→ 开始「打游戏」：只有一条累计在走；切回「喝水」后打游戏暂停；单独结束「喝水」不影响打游戏；结束后喝水离开未结束列表进入历史。
2. 「起床」步骤里开始「喝水」子任务：父事件暂停且保留；子任务笔记独立；结束子任务勾选对应步骤且不自动恢复父事件。
3. 保存单次笔记后折叠；同名新事件不继承；切换未结束事件时各自草稿与已保存笔记正确。
4. 新建习惯后只有一条养成中；切换习惯不改计时；历史保留；侧边栏三级「习惯详情」与历史条目里的「事件详情」入口正确。
5. 结束战报出现且数据与操作一致；记录页按今日/指定日/周/月/全部筛选；知识节点展开方法进入实践；点亮确认；个人主页可到达。
6. 刷新后状态保留且无重复活动计时；窄屏可用；截图 + 浏览器控制台无错误。

## 十、需要用户确认的开放问题

这些是真实歧义，本文不擅自定：

1. **养成口径**：需求书写"每周坚持五次"。旧模拟实现按"不同日期"统计，需求书特别指出不得未经确认加"五个不同日期"的限制。本原型按**次数**统计（同一周内同一天做两次算两次）。若你要的是"五个不同日期"，请明确。
2. **已养成后是否继续累计**：现在按"形成后保留已养成状态，不再参与养成中判定"。是否需要"保持者"机制未定。
3. **候选排序的具体权重**：本轮用可解释的启发式（近期频率 × 时段匹配 × 最近顺序），不显示数值。真实算法未定。
4. **子任务结束后父步骤勾选的时机**：现在"结束即勾选"。是否需要确认步骤完成后再勾选，未定。
5. **公共节点持有者池的分配权重、归因窗口、多节点归因、退款冲销、费率基数与舍入**：产品方向文档已列，仍待定；原型只展示规则与示例账目。
6. **战报是否要"关联知识实践"在未关联知识时留空**：现在留空并显示"本次未关联知识节点"，不补造。
