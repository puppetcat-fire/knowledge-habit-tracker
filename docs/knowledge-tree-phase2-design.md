# 人类知识树 · 二期产品与系统设计文档

> 产品：点亮习惯记录器（一期）→ 人类知识树（二期）
> 首期垂直域：K9（九年义务教育：小学 6 年 + 初中 3 年）
> 试点规模：单人自用 / 小圈子（3–5 人起）
> 版本：v1.0 定稿（概念讨论 + 系统设计 + 决策清单 Q1–Q22 全部已定）

---

## 0. 一句话

让「有人实际做成过」的知识路径，变成**可点亮、可爬行、可治理、可复用**的森林——
个人持有的节点像 GitHub 个人仓库（修改权归个人），群体持有的节点像由点亮者投票治理的 Wikipedia。

## 1. 愿景与定位

### 1.1 从一期到二期

一期「点亮习惯记录器」解决的是**个人证据链**：手动记录 + 计时记录沉淀为可追溯事件，重复动作自动聚合为「节点候选」。

二期「人类知识树」把这条链升级为**共享知识网**：

| 维度 | 一期（现状） | 二期（目标） |
| --- | --- | --- |
| 数据 | 个人本地事件 | 节点 + 路径 + 点亮证据 |
| 节点候选 | 自动聚合，不可编辑 | 可编辑的教程节点，可发布共享 |
| 权威来源 | 自己的记录 | 有人实际做成过的实践路径 |
| 闭环 | 无 | 选中节点 → 指导「下一件要做的事」 |

### 1.2 目标用户

- **学习者**：K9 学生、自学者、家长辅导对象
- **知识整理者**：老师、家长、兴趣作者（建节点、写教程）
- **知识共建者**：点亮者（投票治理）、路径作者（发布爬行路线）

### 1.3 核心价值主张

1. 知识不是静态文档，而是**有人做成过的路径**（实践证据驱动的知识树）
2. 所有权分层：**个人持有 vs 群体持有**，修改权分别归个人和点亮者
3. 双向闭环：**节点 → 指导行动；行动 → 产生证据 → 反哺节点**
4. 创新 = 贡献新方法：**节点是目标，教程是方法**；给节点加第二份教程就是创新，与历史发明者同侪评判（见 4.8）
5. 居民自治：森林由点亮者共同治理；**点亮不可购买**，垃圾方法无论投入多少都会被数据冲掉（见 4.11）

### 1.4 终局：更新当下的教育体系

这不是一个「更好的学习工具」，目标是成为**新的教育基础设施**——知识树（内容组织）+ 实践证据（评价）+ 同侪自治（治理），三者构成替代性的教育体系：

- **内容组织**：按知识的天然脉络组织，而不是按行政切片（年级/学期/章节）
- **评价**：点亮证据（做过、会了）取代考试分数作为能力证明
- **治理**：知识资产由点亮者同侪自治，而非出版社/教育机构垄断

路径不是推翻学校，而是提供**平行系统**：学习者可以脱离学校节奏自主前进；树的证据最终**对接（而非对抗）学校评价**——点亮记录是可迁移的能力证明。

扩展路径：二期 K9 试点 → 更多学科 → **三/四期论文级节点**（引用链 = 前置边、复现 = 点亮，见 4.17）——人类知识树的字面实现。

验证顺序：先在小圈子验证「自然脉络组织 > 课标章节组织」「点亮证据 > 考试分数」两个假设，再逐步扩展。

**定位策略（对外）**：先只作为**爬塔游戏**——节点 = 塔层、路径 = 关卡路线、点亮 = 过关成就；**不直接对标 K9、不宣传教育改造**（终局形态保留，但不用于早期宣传）。成熟后的「大学」只是实践材料方便汇集之地，不是机构。

## 2. 核心概念

| 概念 | 定义 |
| --- | --- |
| 节点 Node | 最小知识单元，描述**「达成什么效果」**（目标），不描述怎么达成。带目标验证任务、持有权、版本链 |
| 教程 Tutorial | **方法**：一种实现节点目标的方式。一个节点可有 1..N 份教程（方法），各自有作者、**宿主实例**、可见性、许可证 |
| 创新 Innovation | 给节点贡献一份新方法（第二份、第三份教程）——**随意提交的日常动作**，「创新」只是它可能涌现的属性，不是门槛 |
| 默认折叠 Folded | 系统默认行为：教程先盖住、先尝试，点开才展开。点开动作本身是卡点信号 |
| 点亮 Light up | 用任意一种方法完成节点目标并打卡，留下证据。点亮是**证据事件**，不是永久状态 |
| 路径 Trail | 有序节点序列 = 一条被验证过的学习路线（「爬树」的路线） |
| 爬行 Climb | 沿路径逐个点亮节点的过程。对路径作者是验证，对后来者是投入 |
| 树 Tree | 同一领域内按前置依赖组织的节点网络（DAG） |
| 森林 Forest | 多棵树 / 多领域的总称 |
| 持有权 Ownership | 个人持有 / 群体持有 |
| 治理 Governance | 群体持有节点的修改、分裂、合并由点亮者投票 |
| 许可证 License | 教程级：开源（知识共享类）/ 付费 |
| 建议时长 Estimate | 节点按 **5–15 分钟**工作量设计（10 分钟为中位），一个节点 = 一次可完成的实践单元（一个习惯槽） |
| 前置/后置 Prereq | 时序依赖：必须先点亮 A 才能做 B（DAG 边）。例：有理数 → 一元一次方程 |
| 实例/原理 Instance | 抽象层次关系：具体应用（实例）↔ 通用规律（原理）。例：「追及问题」是「一元一次方程」的实例 |

## 3. K9 九年义务教育：首期垂直域

### 3.1 为什么选它

- **内容权威现成**：课标明确了 K9 必须掌握的知识点集合——内容来源可靠、现成；但**组织方式要按自然脉络重建**，不抄课标层级（见 3.4）
- **前置依赖强**：数学、物理尤其明显（一元一次方程 → 二元一次方程 → 函数），知识树形态最自然
- **原理-实例天然存在**：数学的「概念/法则」与「例题/应用题」就是原理与实例，课标教材直接提供映射
- **点亮证据可机器验证**：练习题可自动判题，这是最强的点亮证据（见 4.2）
- **使用高频**：每天都要学，天然适配习惯记录闭环
- **内容边界清晰**：K9 内容相对稳定，不像前沿知识快速变化

### 3.2 树的结构（按天然知识脉络，不按年级）

```
森林
└── 数学（K9 内容域）
    ├── 数：自然数 → 整数 → 有理数 → 实数
    ├── 运算：四则 → 幂 → 根式
    ├── 代数：代数式 → 方程 → 函数   ← 示例脉络
    ├── 几何：图形认识 → 平行线 → 三角形 → 圆
    └── …
（年级标签不进入骨架：仅作为在校生「学校进度对照」的可选映射）
```

节点示例：「一元一次方程」（目标：会解一元一次方程）

- 目标验证任务：3 道基础题 + 2 道应用题（可自动判题，机证）
- 教程 M1：移项合并法（课标方法，公开，默认折叠）
- 教程 M2：数轴图像法（社区贡献）
- 建议时长：10 分钟（5–15 分钟区间）
- 点亮条件：用任意一种方法完成验证任务并通过机器验证

实例/原理示例：

- 原理节点：「一元一次方程」的解法原理
- 实例节点：「追及问题」「浓度问题」「盈亏问题」→ 都是该原理的实例
- 关系：原理 ↔ 实例双向支撑——卡在原理 → 退去做实例（具体化）；卡在实例 → 回到原理（抽象化）

### 3.3 课标是内容来源，不是组织骨架

K9 落地最大的坑：**课标/教材的组织（年级-学期-章节）是行政切片，不是知识的自然脉络**——「一元一次方程在初一」是行政安排，不是因为逻辑上只能初学。正确姿势：

- **内容从课标提取**：知识点集合、必掌握项——权威且现成（[《义务教育课程标准（2022 年版）》](https://www.pep.com.cn/bks/kcjcjf/xszh/202512/W020251204512126075695.pdf)），知识点前置依赖边参考公开研究（[K12-KGraph](https://ar5iv.labs.arxiv.org/html/2605.09635)）与教材知识结构图
- **组织按自然脉络重建**：树骨架只有两类边——前置/后置（逻辑序：理解 B 在概念上必须理解 A）和实例/原理（抽象层），**年级标签只是在校生的「学校进度对照」映射，不是骨架**
- **树超越系统**：一个初二学生点亮了全部前置，树就允许他学函数——学校说「你才初二」，树说「你已经会了」

### 3.4 防自学机制与现实破法

K9 环境存在系统性的「防自学机制」，产品必须正视并设计破法：

| 防自学机制 | 产品破法 |
| --- | --- |
| 进度行政化：年级/学期由学校定，个体无选择权 | 树不标年级，进度由「前置点亮」决定，不依赖学校许可 |
| 评价绑定：考试只考课标内容，自学不计入 | 树的内容仍覆盖课标（内容权威性），点亮证据可映射为考试能力——替代路径通向应试 |
| 超前/超纲禁令：提前学被禁止 | 定位「课外平行系统」：不在课堂抢跑，在课后/假期提供自主路径 |
| 时间垄断：学校+作业+教辅占满时间 | 5–15 分钟节点粒度：碎片时间可点亮一次——对「没时间自学」的直接回应 |
| 教辅垄断：内容供给被出版社锁死 | 开放知识树社区：内容由点亮者共建，成本趋近于零，人人可贡献新方法 |

## 4. 关键设计决策（概念讨论）

### 4.1 点亮：什么是「真的做过」

点亮必须是有产出的动作，**不能是「看完」**。但验证方式**默认只保留 L1 自证**：

- **点亮 = 像发一条说说**：网络记录你的声明，是否当真由社会机制裁决（可见性、举报、对称升降，见 4.10）。学习完全自驱
- **L2 机证 / L3 他证：降级为可选插件**（5.7 插件体系），不再是信任地基；K9 练习题天然可机证，未来以插件形式接入
- 节点的「验证」= **最小本质的自证提示**（做什么能证明你会了：做一道代表性题 / 讲给别人听 / 写总结）——不是题集；题集（如 3 道 + 2 道）是**实例节点**的内容，不是原理节点的验证
- 点亮是证据事件：`{ 节点, 人, 时间, 证据, 验证方式 }`，不是永久状态；支持复习复点（后续点亮更新掌握度）
- 掌握度分级借鉴 Khan Academy（Attempted → Familiar → Proficient → Mastered）与遗忘衰减：久不实践自动降级，倒逼间隔复习（[Mastery levels 官方说明](https://support.khanacademy.org/hc/tr/articles/5548760867853-How-do-Khan-Academy-s-Mastery-levels-work)、[2018 机制更新](https://support.khanacademy.org/hc/en-us/community/posts/360023249611-Update-Mastery-Mechanics-Changes-September-2018)）
- 证据编码对齐 Open Badges 三层结构（BadgeClass / Assertion / evidence 链接到作品、测试记录），每次点亮天然可反向验证（[Open Badges 2.0](https://www.imsglobal.org/sites/default/files/Badges/OBv2p0Final/history/2.0.html)）

### 4.2 路径与爬行

- 路径 = 有序节点序列；路径作者 = 走过这条路并发布的人
- 爬行 = 沿路径逐个点亮节点；系统显示完成度（点亮数 / 总数）、用时、证据摘要
- 「只要有人做过并发布记录，每个人都可以花时间爬过来」→ 对应机制：路径发布后，任何人对该路径的爬行进度可见（试点期默认公开，可匿名）
- 路径本身也是内容：可收藏、可 fork（基于别人路径生成自己的变体）
- 借鉴 roadmap.sh 的勾选式路线图（节点可勾选、进度百分比持久化）与 Coursera Specialization 的「起点 → 进度 → 毕业设计」旅程（[roadmap.sh](https://roadmap.codex-soft.net/about/)、[Coursera Specializations](https://blog.coursera.org/got-a-question-on-specializations-we-have/)）

### 4.3 所有权：个人 vs 群体

| 维度 | 个人持有 | 群体持有 |
| --- | --- | --- |
| 修改权 | 创建者独享 | 点亮者投票 |
| 分裂（fork 出新节点） | 个人随时可以 | 提案 + 投票 |
| 合并 | 个人决定 | 提案 + 投票 |
| 转让 | 可转让 / 可「捐赠」为群体持有 | 不可转让（属于集体） |
| 类比 | GitHub 个人仓库 | Wikipedia 词条 / DAO |

**从个人到群体的过渡（关键机制）**：

- 个人节点被足够多人点亮后，创建者可主动「捐赠」为群体持有；点亮者也可发起「转群体持有」提案（需投票）
- 反向不可逆：群体节点**不可私有化**（防掠夺），只能分裂出新的个人节点
- 借鉴：GitHub 的「个人仓库 → 组织 transfer」流程（[官方文档](https://docs.github.com/zh/repositories/creating-and-managing-repositories/transferring-a-repository)）可作为「捐赠为群体持有」的交互蓝本

**分裂的语义（时长拆分）**：

- 分裂更像**时长拆分**：一个 1 小时的行动被拆成 4 个 15 分钟节点（5–15 分钟粒度规则，见 4.12）——原节点保留 + 新节点诞生
- 点亮者选边：投过票或明确选择者归入新节点；未表态者默认留在原节点
- 分裂后子树 / 路径关系：以「分裂说明」记录在案，既有路径可重新规划

**合并的语义（同目标合并）**：

- 两个节点**本质上是完成同一件事**、只是教程上有差异 → 合并提案 → **点亮者限时投票**（A 是否与 B 合并）→ 通过后内容归并（教程保留为多方法），点亮记录合并（取并集）
- **合并归属（已定）**：个人节点与群体节点合并后，个人节点从「控制节点」**降格为群体节点中的一个（付费）教程**——内容变成方法 M，原持有者保留**教程级权利**（作者权 + 付费收入权）。**关键约束：必须本人自愿**（强求不了）——不设强制合并；方向性：个人 → 群体允许（自愿），群体 → 个人不允许（群体不可私有化，防掠夺）。两个个人节点合并：双方自愿协商，一方降格为另一方的教程
- **拆分归属（已定）**：群体拆分出的新节点，教程作者可**认领自己的教程**成为个人节点（教程归属作者实例，内容寻址下自然支持）——拆分只是把归属显式化

### 4.4 治理：投票机制

试点期规则（小圈子够用，公网再重设计）：

- **投票权：未蒙尘的点亮者，一人一票**——「未蒙尘」= 点亮过且未因久不实践而降级（蒙尘机制，4.1）。实践过这个知识的人，对这个知识有天然的投票权利
- **活跃度约束**：蒙尘窗口（试点建议 6 个月）内未复点则失去投票资格——刷子必须持续假装，成本陡增
- **提案类型**：转群体持有 / 分裂 / 合并 / 内容重大修改
- **通过门槛**：赞成 ≥ 2/3 且投票人数 ≥ 最小法定人数（试点建议 ≥ 3 人）
- **公网期可升级**：二次方投票、按贡献加权、防女巫（实名 / 邀请制 / 链上凭证）
- 借鉴：Wikipedia 把「谁能改」分成保护梯度（[编辑保护政策](https://zh.wikipedia.org/wiki/Wikipedia:%E7%BC%96%E8%BE%91%E4%BF%9D%E6%8A%A4%E6%94%BF%E7%AD%96)）——对应本系统：新点亮者只能评论，老点亮者可提案，核心维护者可直接改小错。DAO 的二次方投票能防多数暴政但本身怕女巫攻击（[Quadratic voting](https://en.wikipedia.org/wiki/Quadratic_voting)、[Gitcoin Passport](https://docs.passport.gitcoin.co/)），试点期不引入

### 4.5 收费与开源

- 每个节点带许可证：**开源**（CC BY-SA 类）或**付费**
- 个人持有付费节点：收入归个人
- 群体持有付费节点：收入按贡献分成（点亮者 / 维护者）；试点期先记账、不分账
- 爬树预览免费（标题 / 路径可见），点亮需解锁付费节点
- **试点期红线**：K9 面向未成年人，先不做真实支付，只做「付费标记 + 申请解锁」模拟，验证需求后再评估真实支付（未成年人消费、数字内容退款等法律问题另行评估）
- 变现模式建议走 **open core**（GitLab 模式）：节点正文开源，增值部分收费。K9 场景的增值点：AI 讲解、自动批改报告、结业证书。参考：知乎盐选的内容分成、[小报童](https://xiaobot.net/)订阅、[GitHub Sponsors](https://github.com/sponsors) 订阅赞助
- **收费落到教程（方法）级，不是节点级**：标准方法（如课标解法）不可收费；作者原创的新方法可单独设付费/门控（详见 4.8）

### 4.6 双向闭环：知识树 ↔ 事件记录器

这是二期最独特、最值得做的部分：

1. 用户**选中节点** → 节点教程中的「实践任务」被转换为**下一件要做的事**，投喂给一期事件记录器（成为今天的待办）；任务带**完成条件**（按节点建议时长 5–15 分钟 + 机证标准，如判题规则），打卡结果才可回流
2. 用户**完成 → 打卡** → 事件沉淀 → 证据回传节点 → **点亮**
3. **未完成 / 失败** → 卡点数据回传节点（卡点榜：该节点哪一步最容易卡住——作者据此改进教程）
4. 闭环收益：一期的事件证据链升级为二期的点亮证据；二期的知识树让一期的「每天做什么」有依据
- 借鉴 GTD / PDCA 的「计划 → 执行 → 复盘」回路（日事清、滴答清单的连续天数统计）：节点的卡点数据就是复盘输入，回传作者改进教程（[滴答清单习惯追踪](https://clickup.com/learn/topic/productivity/tools/features/habit-tracking/)）
- **定位确认**：闭环弥补「事件记录 → 习惯管理」的**长期任务规划缺口**——知识树提供长期目标与顺序，习惯系统提供重复节奏，两者**一定程度上并行**（4.13 三条线）

### 4.7 数据与隐私边界（延续一期本地优先）

- 个人草稿、未发布节点、个人点亮记录：**本地优先**（沿用一期 localStorage / JSON 备份）
- **本地点亮**：可以只用教程、点亮记录**不上传网络**——完全本地/私有的实践与点亮；只有你想让它在森林里被看见时才发布（发布到森林才上服务端）
- 发布到森林：才上服务端（节点内容、路径、点亮证据摘要）——明确的选择性例外，可撤销
- 爬行进度：默认公开（是森林的养料），可匿名化
- K9 面向未成年人：敏感数据（真实姓名 / 学校）默认不采集

**数据不出本地与跨终端对齐**：

- 原则：个人习惯数据（事件 / 习惯 / 点亮草稿）**默认不出本地**——浏览器 / Electron / Android 各自独立存储，互不相同步
- 问题：跨终端不齐（一期现状：Electron 与浏览器 localStorage 隔离）
- 解法（按优先级）：
  - 试点期：手动 JSON 导入导出（一期已有）
  - 远期：**E2E 加密同步**——数据加密后上传，服务端零知识（只存密文），本地密钥恢复——「出本地但不出明文」
  - 可选：局域网直连同步（同网设备，无需服务器）；自托管同步
- 与「共享默认关闭」（4.16）一致：不出本地是默认，加密同步是受控例外

### 4.8 节点 = 目标，教程 = 方法（提交教程 = 随意动作）

「节点是目标，教程是方法」让数据模型更干净：

- **节点描述「达成什么效果」，不描述「怎么达成」**
- **教程是方法**：一个节点下可以有 1..N 份教程，每份教程是一种实现该目标的方式
- **提交教程是随意提交的日常动作**：不标榜「创新」——任何人都可以随时给节点贡献一份新方法（M2、M3……）；「创新」只是它可能涌现的属性，不是门槛
- **上传教程必须首次点亮**：提交教程前，作者必须先点亮该节点（我做过，才教人）——信任门槛，与商家挂载需点亮记录同源（5.7）
- **教程默认折叠是系统行为**：不是付费功能，实现只是一个开关——做事之前教程先盖住、先尝试，点开才展开

```
节点 B（目标：会解一元一次方程）
├── 教程 M1：移项合并法（课标方法，公开）
├── 教程 M2：数轴图像法（社区贡献，公开）
├── 教程 M3：拆项配平法（作者原创，可选付费/门控）
└── …（方法可随意持续增加，每加一份 = 一个普通动作，创新是涌现属性）
```

由此推导：

- **点亮判的是目标，不是方法**：机证任务挂在节点上（验证「达成效果」），用 M1 还是 M3 达成都算点亮
- **方法有数据**：每次点亮记录「用了哪个方法」→ 方法有效性 = 点亮率 / 卡点率，作者据此迭代
- **可见性两级**：① 系统默认折叠（人人可用，先尝试后展开）；② 作者可选门控（原创方法可设付费 / 点亮兑换 / 求助解锁，见 4.9）
- **质量由数据说话**：方法好不好 = 点亮率 / 卡点率 / 同侪点赞 / 举报（4.10）——不能帮人达成目标的教程会被数据淘汰
- **治理对象变化**：节点（目标定义）的修改 = 作者审（个人）/ 投票（群体）；教程（方法）的增删 = 类 PR——个人持有由作者审，群体持有由同侪评判
- **收录机制：同侪评判，不设权威审核**——新方法门槛：同侪（点亮过该节点的人）点赞达阈值自动收录；「方法能用」由**黄线复现**把关（4.10），复现失败的教程沉底。「同侪」= 点亮过该节点的人（面对过同一目标的人），点赞权重最高；未点亮者的浏览点赞权重低
- **设计哲学：学习者即发明者**——当你发明 M3 时，你和发明「移项合并法」的历史人物站在同一位置：你的方法被同样的规则评判（能否点亮目标 + 同侪是否认可），不因身份、资历而有差别。知识树因此不只是在消费知识，而是在**再生产「创造」这件事本身**——这是最强的创新训练

### 4.9 卡点时刻：从 A 到 B 的知识缺口与求助模型

「处于节点 A、想做节点 B、不知道怎么做」是产品最核心的交互时刻。配合「教程默认折叠」，学习者的真实思考链与系统对应如下：

| 第几步 | 人的真实想法 | 系统行为 |
| --- | --- | --- |
| 1 | 「我先自己试试」 | **默认状态：教程折叠**。只显示 B 的目标 + 前置检查（A 的掌握度够不够）。尝试过程被事件记录器记录 |
| 2 | 「有没有人做过？」 | 点亮者列表 + 证据样例（他们用了哪个方法）——这是「爬」的核心价值 |
| 3 | 「我该看哪个方法？」 | 教程列表（M1/M2/M3…）默认折叠，**点开即展开**——点开动作本身就是卡点信号 |
| 4 | 「这个方法不会，能问谁？」 | **求助点亮者**：问用过该方法的人（点亮 = 有资格回答），应答成为互动证据（他证升级） |
| 5 | 「我卡住了」 | 卡点上报（记录卡在哪份方法、哪一步）→ 通知该教程作者 → 迭代（闭环） |
| 6 | 「这方法不行，换一个 / 我自己发明」 | 换方法 = 方法有效性数据；发明新方法 = 贡献 M(n+1)（机证 + 同侪点赞自动收录，**与历史发明者同位**） |

关键设计原则：**默认折叠是「先尝试」的 UX；门控（若作者选择）永远不能阻断学习**。即使某份方法教程被门控，学习者始终有替代路径——其他方法教程 / 求助点亮者 / 独立尝试。门控只能控制「方法内容」，不能控制「点亮本身」，否则知识树就变成付费墙。

方法教程的门控（作者可选，试点期可选做）：

- **付费解锁**：作者原创方法的 open core 增值
- **点亮兑换**：用其他节点的点亮记录换取解锁（贡献换知识，社区经济）
- **求助解锁**：向用过该方法的点亮者提问并获答后解锁（他证互动，验证真实性）

**悬赏教程（新）**：

- 场景：「我有想实现的效果，但不知道怎么做」→ 挂出**悬赏节点**（公开 / 非公开），悬赏出教程
- 悬赏 = **bounty issue**（一种 issue 类型，见 4.10）
- 结算：悬赏者定金额与验收方式；**验收靠人**——悬赏者本人确认（人治，无系统验收）；金额与方式公开
- 意义：创新市场的**需求侧**——不是等人恰好发明，而是**主动出价购买方法**

### 4.10 信任设计：默认信任，结构自证（为什么要防作弊）

防作弊不是目的，保护「信任」这个核心资产才是。先回答反问题：**个人学习需要防作弊吗？不需要——骗自己亏自己**。点亮记录是假的，损失最大的是点亮者本人。

真正需要防的，是**会伤害他人的作弊**，只有三种：

1. **假点亮 → 假投票权**：点亮赋予治理权（群体节点分裂 / 合并投票），假点亮 = 女巫攻击治理
2. **假点赞 → 低质方法收录**：同侪点赞驱动方法收录，假点赞 = 垃圾方法污染森林
3. **假路径 → 浪费爬行者时间**：路径的价值主张是「有人真的做成过」，假记录让后来者白花时间——**时间是这个森林里爬行者支付的货币**

设计原则：

- **人防 > 系统防**：点亮、教程都可以被举报；用「对称升降」——**怎么刷上来，就怎么刷下去**（点亮多的教程优先推荐，被举报 / 无效的教程沉底）。利用使用者的力量，让刷上来的掉下去
- **点亮本身是点赞效应**：点亮多的教程被优先推荐——推荐排序由真实点亮驱动，不用系统规则硬判
- **防作弊强度 = 伤害范围**：个人动作（自证打卡）不设防；公共动作（投票 / 点赞 / 发布）靠社会机制防
- **成本不对称**：蒙尘投票（4.4）要求刷子持续假装；首次点亮门槛（4.8）要求教程作者真做过——作弊成本随时间累积，收益随时间归零
- **issue 分级（已定）**：举报教程 / 节点问题 = 在该对象上开 **issue**（GitHub 式）——公开、可评论、可加标签、可关闭：
  - **绿线**：教程本身需要展开说明——作者 / 维护者的待办输入（4.19 维护工作的来源之一）
  - **黄线**：**无法复现**——方法按教程做不出来；多次黄线 = 复现失败信号 → 教程沉底（**人治版机证**：L1 时代「方法必须能用」由同侪复现把关）
  - **红线**：违反法律法规（4.20）——**不公开**，直接进入平台 / 实例内部审核；**每账号仅 3 次**（稀缺资源防滥用，误报即消耗额度）
- **悬赏 = bounty issue、卡点 = issue 来源、意见反馈（C4）并入同一层——issue = 森林的问题层；恶意举报靠生态自净（spam 标签 + 关闭 + 点亮信誉加权）**
- **激励出现前不需要重防**：试点期无排名、无证书、无金钱；公网期引入激励时，防欺诈成本由激励方承担
- **默认信任**：系统不假设用户是骗子；诚实是最省力的路径

### 4.11 居民自治：错误的活不下去，钱也救不了

社区自治的核心不是「投票选谁是对的」，而是**「结构让错的活不下去」**：

- **点亮不可购买（L1 时代的重新表述）**：点亮是公开的社交声明（像说说，4.1）——钱可以买到展示位、门控解锁、营销投放，但买不到「持续真实」：刷出来的点亮会被举报、会因蒙尘失效、会被对称升降机制冲下去——**怎么刷上来，怎么刷下去**
- **淘汰是结构性的**：垃圾方法点不亮目标（机证不过）→ 卡点数据堆积 → 同侪点赞为零 → 自动沉底。投入越多，沉底越快（花大钱推一个没用方法，成本完全打水漂）
- **数据公开 = 自治可见**：森林统计数据（点亮数、卡点率、方法有效性）默认公开。淘汰过程可观察、可审计——「被冲掉」要能被看见，居民才能自治
- **他证节点的缝隙**：实验 / 作品类（他证）是资本可钻的缝隙（雇人点赞 / 审核）。试点期靠小圈子社会信任封住；公网期这类节点要么限权（只有点亮过的人能他证），要么引入更重的结构。机证节点永远免疫——「真实」被定义为机器可验证的产物，而非人为声明

### 4.12 节点粒度与关系：5–15 分钟、前置/后置、实例/原理

**节点粒度：一个节点 = 5–15 分钟可完成的实践单元**

- 建议完成时长 5–15 分钟（10 分钟为中位数）——这是「今天就能点亮一次」的单元，正好是一期计时器的一次专注（一个番茄）
- **节点就是习惯单元**：一节点 → 一任务槽，TodoBridge 按节点建议时长生成「下一件要做的事」
- **粒度规则**：目标超过 15 分钟 → 拆成多个节点（形成前置/后置链）；低于 5 分钟 → 考虑并入相邻节点
- **实际时长是结构信号**：普遍超时 = 节点太大（拆）或前置不足（补）；普遍偏快 = 可以合并。节点大小由数据说话，不凭感觉

**两类节点关系**

| 关系 | 含义 | 例子 | 用途 |
| --- | --- | --- | --- |
| 前置/后置 | **推荐序（非强制）**：先点亮 A 通常利于做 B；边界/易错节点可挂到上一节点的多个子节点上 | 有理数运算 → 一元一次方程 → 二元一次方程 | 爬行路径的推荐顺序 |
| 实例/原理 | 抽象层次：具体应用 ↔ 通用规律 | 「追及问题」是「一元一次方程」的实例 | 卡点解法维度 + 复习素材 + 创新来源 |

实例/原理关系的价值：

- **卡点时刻多一个解法维度**：卡在原理 → 退去做实例（具体化）；卡在实例 → 回到原理（抽象化）——具体↔抽象双向学习回路
- **复习的无限素材**：原理节点的复点可以随机换实例练习（实例库 = 复习题库），实例越多原理越牢
- **创新的另一面**：一份新教程可能是「原理的新实例」（新应用场景），也可能是「实例集的新抽象」（新原理）

**前置是推荐，不是强制**：

- 硬上更难的节点当然可以——**跳关不推荐但支持**；跳关后卡关会自然回流补前置
- **跳关成功 = 开辟一条新的学习路径**：树的顺序基于乐于分享用户的实际使用时序大数据推荐（协作涌现），不是专家铁律
- **学霸特质复刻**：学霸知道自己会了——系统目标之一，是帮每个用户获得准确的掌握自知（元认知：我知道自己会了什么、不会什么）

### 4.13 三条线：推荐行动 / 事件记录 / 习惯管理（同一事件底层）

用户感知是三个页签，但底层是**同一个「事件」实体**——三条线不是三个平行系统，而是同一事件底层的三种视图：

| 页签 | 时态 | 本质 |
| --- | --- | --- |
| 推荐行动 | 未来时 | **待发生的事件**：由知识树节点任务生成（5–15 分钟槽，带完成条件、来源节点） |
| 事件记录 | 现在/过去时 | **已发生的事件流**：手动记录 + 计时记录 + 推荐行动完成后的沉淀，全部可追溯（证据链） |
| 习惯管理 | 反复时 | **事件的重复归纳**：同一来源重复 N 次 → 聚合为「节点候选」→ 正式化为习惯 |

冲突的解法：**习惯不是事件的容器，是事件的归纳视图**。

- 「事件都是习惯的实例」只在归纳层成立：被重复模式吸收的事件才是习惯的实例
- **单次非习惯事件（含推荐行动的单次完成）就是底层事件本身**，不强制归入任何习惯——记录它、沉淀它、点亮节点，但它不进习惯管理
- 一次点亮 = 一次事件，不是习惯；重复点亮同一节点 = 模式浮现，才是习惯/复习节奏的来源
- 「一次只养一个习惯」的一期约束保留在**习惯管理页签内**，不限制事件记录和推荐行动两条线

关系链：

```
知识树节点任务 → 推荐行动（待办事件，带完成条件）
    → 完成 → 事件记录（证据链）
    → 点亮节点（二期）
    → 重复 N 次 → 习惯管理（节点候选 → 习惯）
    → 卡住 → 事件记录留「卡点」标记 → 回传作者
```

数据模型：`Event` 增加 `source`（manual / timer / node-task）；`TodoBridge` 折叠进 `Event`（推荐行动 = `source='node-task'` 且 `status='pending'` 的事件）

### 4.14 隐形课堂：树即社交图谱

树做大之后，社交是**派生的**而不是设计出来的功能——**你在树上的位置决定你的关系**：

| 树上的位置 | 社会角色 | 机制 |
| --- | --- | --- |
| 正在爬同一节点/路径 | 同窗（隐形同桌） | 节点页显示「此刻同窗」，形成陪伴与同伴压力 |
| 点亮了该节点 | 学长 | 求助点亮者（4.9）——同侪评判的社交面 |
| 写了某份方法 | 助教 | 方法作者答疑，方法有效性数据驱动迭代 |
| 发布了某条路径 | 向导 | 路径被收藏/被爬，向导获得认可与收入 |

- **位置社交，不做广场**：不需要好友系统、班级功能、信息流——爬同一棵树本身就是同学关系；匿名爬行者只贡献数据、不进入社交（与 4.7 一致）
- 隐形课堂 = 求助机制 + 同侪评判的规模化：小圈子是手动点名求助，大树是同窗自动浮现
- 爬同一路径的人 = 天然小班；同一时刻在附近节点的人 = 即时互助

### 4.15 商业化：盈利模式与信任红线

**信任红线：商业化只能发生在展示与增值层；排序、点亮、收录永远不可购买。**

| 盈利模式 | 说明 | 信任约束 |
| --- | --- | --- |
| 商家产品挂载 | 商家在自己（或相关）实践节点挂产品，佣金按**机构自设比例**（默认参考 0.5%，见 5.7） | **挂载前提 = 商家拥有该节点的点亮记录**（他真做过）——钱买展示位，买不到点亮 |
| open core 增值 | AI 讲解 / 自动批改报告 / 结业证书 | 增值层收费，正文开源 |
| 原创方法门控 | 付费 / 点亮兑换 / 求助解锁（4.9） | 门控不阻断学习，替代路径永在 |
| 隐形课堂付费小班 | 学长带新人，平台抽成 | 学长必须有该节点点亮记录 |
| B 端机构入驻 | 机构/学校把课程建成树（入驻费） | 机构的树也要接受同侪评判 |
| 证书/能力证明 | 点亮记录对接学校评价/升学（1.4 终局） | 证书基于机证，不可购买 |
| Pro 订阅 | 高级统计、无限节点等 | 低优先，不阻塞核心体验 |
| 赞赏（下一杯咖啡） | 习惯养成后的感激式微付费（0.5–5 元，自愿） | 只在感恩时刻出现一次，可永久关闭；文案引导推荐而非赞赏 |
| 节点维护服务 | 蒙尘机制下的职业维护者（持续复点、更新教程、响应 issue，见 4.19） | 维护者须未蒙尘点亮过该节点；费用透明 |

0.5% 是**默认参考比例**，各机构（托管树的社区）可自设提成比例（见 5.7）。**个人收入同样抽 0.5% 佣金**（平台 / 实例）。设计意图：**靠规模不靠榨取**——低到商家没有 spam 动力，长尾商家（小作坊/个人卖家）也进得来；「结构让错的活不下去」延伸到商业层，商家 spam 挂载会因点亮证据不足 / 同侪零认可自动沉底。

**K9 免费红线**：义务教育内容**免费提供**，不收节点费。收费项目集中在**增值内容**——特殊案例的解题思路、原创方法门控（4.9）、悬赏教程（4.9）等，而不是课标核心内容。

**证书模式弱化**：纯 L1 自证支撑不了「机证证书」——「证书 / 能力证明」盈利模式改为「点亮记录 + 社会背书」（点亮数、未蒙尘时长、同侪认可），或推迟到公网期重新评估。

收入去向（已定）：挂在别人节点的产品，佣金分成给**节点持有者 / 方法作者**（试点期先记账不分账，比例由机构设定时一并约定，默认作者得大头）

### 4.16 数据共享与学术研究

森林的运行数据（点亮、卡点、路径、方法有效性）是教育学研究的独特金矿——**实践证据数据集**，比考试分数 / 问卷丰富得多。共享必须由居民决定、分级、可撤回：

- **默认状态：全部默认关闭（opt-in）**——包括 L1 匿名聚合；用户主动开启才共享，可随时撤回。共享是居民主动让渡的，不是平台默认拿走的
- **分级共享**（开启后按级别放行）：
  - L1 匿名聚合（统计级：节点点亮数、卡点率）——低风险，开启门槛最低
  - L2 脱敏个体数据（去标识化的爬行轨迹）——需显式同意
  - L3 实名数据——需强同意 + 研究用途审批
- **研究者申请-审批**：提交申请（用途、方法、隐私方案）→ 审核 → 只提供审批范围内的数据 → 违规即终止 + 追责
- **回馈闭环**：研究结果回馈森林（改进树 / 方法 / 卡点预测），数据贡献者看得见自己的数据产生了什么——共享不是单方面付出
- **默认关闭的代价与激励**：研究数据要靠「回馈闭环」吸引用户主动开启——用户看得见共享带来的价值（树更准、卡点被预测、学习方法被研究改进），才愿意打开开关
- **未成年人红线**：K9 用户数据只允许 L1 匿名聚合，且需监护人同意
- 与居民自治一致：数据共享不是平台单方决定，是「居民决定 + 平台执行」

### 4.17 三/四期：论文即教程节点（人类知识树的字面实现）

扩展路径：K9（规范域试点）→ 更多学科 → **论文级节点**。树做大了之后，一篇论文就是一个教程节点，映射几乎完美：

- **节点 = 论文**：目标 = 论文声称的贡献；教程 = 论文方法论（默认折叠——先尝试复现，点开才看方法）
- **点亮一篇论文 = 复现它**：「有人做成过」的学术版——复现点亮记录成为论文可信度的新度量
- **引用链 = 前置边**：论文 A 引用 B = B 是 A 的前置——引用网络天然就是知识树的前置依赖
- **综述 = 原理集；数据集 / 实证 = 实例库**：实例/原理关系在学术域自然成立
- **创新 = 新论文 / 新方法**：给论文节点贡献新方法（不同实现路线）或新实例（新数据集复现）
- **同侪评判的意义**：影响因子可以被买卖，**复现不能**——「点亮不可购买」延伸到学术界，成为超越影响因子的知识评价基础设施
- **治理**：学术争议（优先权、正确性）→ 投票 / 仲裁，版本链保存论争过程
- **与研究共享闭环**：森林数据（4.16）→ 学术研究 → 新论文 → 新节点 → 森林受益

### 4.18 赞赏时刻（下一杯咖啡原则）与口碑传播

- **触发**：习惯养成后（连续达成 / 点亮里程碑）——情绪高点、感恩时刻；只出现一次，可永久关闭，不弹窗骚扰
- **金额**：0.5–5 元——**下一杯咖啡原则**：小、自愿、不强迫、与「买杯咖啡感谢作者」同构
- **文案即理念**：赞赏页同时传达公司理念与——「比起赞赏，我们更希望你把它推荐给身边的朋友使用」——支付页变成理念传播页 + 口碑增长页
- **本质**：不是主要盈利模式，是**理念验证 + 口碑增长机制**——愿意赞赏的人 = 高认同用户 = 推荐种子；赞赏行为本身是「用户价值信号」
- **与 4.15 关系**：感激式微付费（第 8 条），定位在「理念层」而非「收入层」

### 4.19 维护模型：个人维护 / 点亮者维护 / 维护者职业（人治）

- **个人持有节点：作者自己维护**——改教程、响应 issue、保持「可用别太烂」
- **群体持有节点：点亮者维护**——未蒙尘点亮者天然有维护资格（同投票权，4.4）；重大修改投票、小错直接改（Wikipedia 梯度，4.4）；无人维护 → 休眠 / 归档，可被接管
- **蒙尘成本催生职业**：蒙尘机制让「保持节点点亮」有持续成本（要持续复点）→ 引生**节点维护者职业**（付费服务：持续复点、更新教程、响应卡点与 issue、保持节点可用）——同时市场化解法死节点（9 风险 2）
- **人治，不是系统治**：**无系统级验收机制**——用户自己知道做到了；教程质量底线 = 「可用别太烂」（有人能用它点亮目标即可）；烂教程靠对称升降沉底（4.10）
- 维护者职业的收入：订阅 / 按节点付费 / 悬赏分成（并入 4.15 盈利模式）

### 4.20 红线层：法定禁止内容（人治管质量，红线管合法性）

「言论自由、技术中立」是真的，但平台有**承载边界**——法定禁止内容（毒品制作、邪教传教、洗脑操控、危害未成年人、危害国家安全等）不是「质量差」的问题，是**法律责任**问题。且「对称升降」对恶意但**有效**的教程（毒品/洗脑教程能帮人达成目标、会被正常点亮推荐）**结构性无效**——纯人治管「可用性」，管不了「合法性」：

- **红线 ≠ 审核**：红线是**法律定义的最小禁止集**（确定性、不可协商、不参与投票）；内容质量永远人治（4.19）——**人治管质量，红线管合法性**
- **红线是联邦的最低入会条件**：任何实例必须执行法定红线，否则被联邦拒绝 / 隔离（不接壤违规实例）——居民自治不豁免法律义务
- **红线处理权在实例运营者**：不是投票、不是同侪——法定义务不能交给投票；红线举报 = 最高优先级 issue 但**不公开**（直接进入平台 / 实例内部审核，避免公开私刑与滥用）；**每账号限 3 次**（稀缺资源，误报即消耗额度）；审核确认后限期下线 / 隐藏 / 移除出联邦
- **系统辅助 + 人裁决**：系统可标记「疑似红线」（关键词 / 已知类别），最终由人（实例运营者）裁决——系统不裁决内容好坏，只辅助
- **K9 加严**：面向未成年人，红线清单更严、执行更快（未成年人保护法加重责任）
- **言论自由边界**：红线针对的是**可执行的危害教程**，不是思想表达——「毒品的危害讨论」可以承载，「毒品制作教程」不行。这个产品恰好是教程化的（节点 = 做成过的方法），对可执行危害内容的责任是产品特性带来的，必须由平台 / 实例扛
- **反规避**：改头换面的教程（暗语 / 包装）靠居民举报（红线举报无门槛）+ 实例义务

### 5.2 版本控制：内容寻址（类似 git）

- 节点内容**不可变**：每次修改生成新版本（content hash）
- 节点指针指向当前版本，历史版本可回溯
- fork = 基于某版本复制出新节点；merge = 提案合并版本链
- 好处：分裂 / 合并 / 回滚都基于版本，天然支撑「更大的 GitHub」

### 5.3 分发形态：AI skill 与插件（产品即协议）

整个产品本质上是「一套教学法协议」——默认折叠、卡点时刻、同侪评判、点亮证据都是**可移植的指令和数据结构**，不是某个 App 的私有逻辑。因此：

- **AI skill 形态**：一个可加载的 skill 包 = ① 树数据文件（节点 / 边 / 教程，标准 JSON）② 工具定义（点亮、取下一个行动、提交方法、上报卡点、发起提案）③ 教学法指令（先尝试不剧透、卡住才求助、同侪评判规则）。任何 AI agent 加载即能教书——数据模型与 API 草案直接成为 skill 的 schema
- **MCP 形态（标准接线）**：
  - 粒度：**一棵树一个 MCP server**（不是每节点一个——连接会爆炸）；一个进程可挂多棵树按 treeId 路由；「个人事件域」（事件 / 习惯 / 推荐行动）可作为第二个 server
  - 节点 = content-addressed resource：`tree://k9-math/nodes/eq-101`；教程 = 子资源；点亮 / 推荐行动 / 提交教程（`submit_tutorial`，一等功能）/ 创建节点（`create_node`）/ 上报卡点 / 提案投票 = MCP tools；教学法 = MCP prompts（默认折叠、卡点时刻、同侪评判）
- **插件形态**：Obsidian / 笔记软件插件（树的可视化 + 点亮记录）、浏览器插件（推荐行动入口）、编辑器插件
- **Android 客户端（必须）**：完整客户端承载三条线（推荐行动 / 事件记录 / 习惯管理）+ 树浏览 + 点亮，悬浮计时条复用一期 overlay。5–15 分钟节点就是手机碎片时间的单元，爬树天然是移动行为；手机是森林里的一个节点，数据存设备本地
- **APK 分发**：试点期侧载（不走应用商店，贴合小圈子 + K9 未成年人合规），后期再评估商店

### 5.4 确定性核心与 AI 附件（无 API key 可用）

「没有 apikey 也能使用」是硬约束，靠分层实现：

- **确定性程序（零 AI 依赖，核心闭环全部在此）**：机证判题、点亮记录、版本链、投票计票、卡点聚合、默认折叠逻辑、时间预算检查
- **AI 模式（可选附件，有本地模型 / API 才启用）**：辅导对话、提示生成、方法写作辅助、路径推荐
- **铁律：AI 永远不承担「验证」职责**——验证必须确定性程序（客观、可复现、不可购买）；skill/MCP 用「写死的程序」驱动确定性部分，AI 模式只做教学与生成
- **无 key 保证**：核心闭环（树 → 推荐行动 → 完成 → 机证 → 点亮 → 卡点）全程无 LLM 依赖；AI 层整体可降级关闭，纯本地程序流照常运转
- 与本地优先 / 隐私 / 无集群一致：不依赖任何外部 AI API

### 5.5 规范即产品（我们制定的约束与规范）

交付的不是 App，是**协议**——任何实现遵守规范即可接入森林：

- **树数据结构规范**：节点 / 边（前置·实例）/ 教程 / 证据 / 版本链的 schema（第 6 节）
- **教学法约束**：默认折叠、卡点时刻、同侪评判、点亮不可购买、门控不阻断学习
- **工具接口规范**：MCP 工具集（= 第 7 节 API 草案的标准化）
- **验证规范**：机证判定规则、证据分级 L1/L2/L3、点亮证据编码（Open Badges 结构）

官方客户端、社区 skill、第三方插件都只是规范的实例——与 5.3「产品即协议」、5.6 联邦化是同一件事的三个面。

### 5.6 基础设施现实：无集群，联邦化（居民自治的架构版）

「负担不起大规模集群」不是妥协，而是印证了架构方向——**这个系统本就不该有中心化大集群**：

- **树是分布式的**：每个小圈子自托管自己的树（一棵树 = JSON 文件 + 小服务），数据不出本地（4.7）天然成立
- **树与树联邦互通**：轻量联邦协议（类似 ActivityPub）交换——发布的节点、点亮证据摘要、提案；「人类知识树」是**森林联邦**，不是一台巨型数据库
- **算力即社区**：森林的算力 = 参与者的设备之和；居民自治（4.11）在架构层就是自托管 + 联邦
- **论文级节点（4.17）**：未来是各实验室 / 社区自托管的学术树联邦，不是中央文献库
- 试点期：单机 JSON + 局域网即可；联邦协议是远期演进，不阻塞 MVP

### 5.7 机构自治经济与开放插件

**机构 = 托管一棵（或多棵）树的运营单元**（家庭 / 学校 / 公司 / 兴趣社区）——与「一棵树 = 一个 MCP server = 一个联邦单元」同粒度：

- **提成比例 = 树级配置**：个人持有的树由持有者设定；群体持有的树由点亮者投票设定（治理模型延伸到经济层）。默认参考 0.5%，规范可设上限（如 ≤10%）防乱收费
- **比例公开透明**：挂在树页，爬行者 / 商家可见，作为选择树的依据——联邦经济靠透明与自治竞争，不靠平台强制
- **居民自治延伸到经济层**：树的经济规则由树的居民决定，不由平台决定

**提交教程节点（一等功能）**：

- MCP 工具：`create_node`（提出新目标）、`submit_tutorial`（给节点贡献新方法）
- 流程：机证（方法必须能点亮目标）→ 同侪点赞达阈值自动收录；个人持有节点由作者审——提交是低门槛高频动作，鼓励创新（4.8 / Q8）

**开放性功能插件**：

- 遵循规范（5.5）的第三方扩展：新验证器（手写判题、语音评测、实验数据解析）、新教学法组件（间隔复习、遗忘曲线）、新可视化（树图布局）、新分发（社区 skill / MCP server / 插件）
- **插件增加能力，不改变信任结构**：点亮记录的真实性、投票计票、版本链完整性不可插件化；新增验证器须开源可审计（验证仍是确定性程序，5.4 铁律）
- 分发：社区自托管（GitHub / 自托管），无中央商店——与无集群 / 联邦一致

### 5.8 虚拟森林：跨树缝合，用户不感知归属

联邦不能是孤岛——用户感知必须是**一个完整的大网**，物理上的一棵棵树由后台缝合：

- **全局寻址**：`tree://{treeId}/nodes/{nodeId}@{versionHash}`——**地址即归属**；后台用它解析与拼接，用户界面不展示归属（像网页不显示服务器 IP）
- **内容寻址 + 不可变版本（5.2）= 跨树边永不断链**：边指向不可变对象，旧版本永远存在——这是 web / git 能成立的根本原因，也是「后台连线不乱」的保证。乱只有一个来源：边指向会变的本地 ID；换成全局地址 + 内容寻址，乱即消失
- **边是链接，拼接发生在读取时**：跨树边 = 链接，解析 = 按地址从宿主树取（ActivityPub 式 fetch），可缓存 / 镜像（内容不可变，缓存安全）——**没有中央数据库在做合并**，写入时零中央依赖，集群依然不需要
- **用户不感知归属**：UI 只显示一个森林 + 领域脉络；归属（哪个机构托管）只在需要时浮现——治理（投票 / 编辑时显示持有权）、交易（显示机构提成比例）
- **搜索与发现**：可选轻量「树索引」（树注册表，类似 DNS）帮助跨树搜索；图的本身不需要索引——网由链接涌现
- **大网的真相**：没有任何人看得见完整的「人类知识树」——网是涌现的，每个用户只看见自己爬行的邻域；这正是它与「集中式巨型数据库」的本质区别，也正好不需要集群
- **归属粒度：节点级 + 教程级**——同一节点的不同教程可以归属不同实例：教程内容留在**作者自己的实例**上（数据不出本地的纯粹形态），节点只是链接。教程地址 = `tree://{treeId}/nodes/{nodeId}/tutorials/{tid}@{ver}`，宿主可为任意实例
- **跨实例同侪聚合**：点赞用「实例见证 + 签名计数」——每个实例为自家居民的点赞背书（签名），聚合 = 跨实例签名计数之和；真实性由机证兜底（假点赞需要假点亮，假点亮过不了机证）——信任结构不因跨实例而破
- **教程级经济自治**：付费教程的提成按**作者所在实例**的比例（5.7 的机构自治延伸到方法层）；用户界面依然只显示 M1/M2/M3，归属在付费 / 治理时浮现

### 5.9 网络现实：离线优先与波动适配

联邦 + 本地优先在真实部署下的网络原则——**离线是常态，不是异常**：

- **核心闭环全程零网络**：树 → 推荐行动 → 完成 → 机证（本地确定性程序，5.4）→ 点亮 → 卡点，全部本地可跑——飞机上 / 地铁里 / 无信号地区照常点亮
- **同步异步、最终一致**：有网就同步，无网就排队；节点是内容寻址的不可变版本、事件是追加式——**冲突天然极少**（追加无冲突；可编辑的草稿类才需合并策略，见 Q19）
- **内容寻址 = 幂等 + 缓存安全**：跨网络操作天然幂等可重试（同样请求同样结果）；不可变内容缓存**永远有效**——弱网重试与降级的底气
- **优雅降级**：跨树取数失败 → 显示本地缓存或「暂不可达」+ 全局地址，不阻断本地核心
- **波动适配**：请求幂等键、增量同步（只传变化版本）、元数据优先（教程折叠本来就是先元数据后内容）、移动端断网重连自动续传
- **联邦隔离性**：一棵树 / 一个实例挂了不影响其他——可用性靠隔离，不靠中心
- **MCP stdio 本地进程 = AI 层零网络问题**；本地模型（无 key）更是完全离线

## 9. 风险与开放问题

### 风险

1. **反作弊**：见 4.10——强度与伤害范围成正比；试点期靠小圈子信任 + 机证即可，公网期引入激励（付费 / 证书 / 排名）时才需重防，成本由激励方承担
2. **死节点**：群体持有但无人维护 → 休眠 / 归档 / 可被接管；维护者职业（4.19）提供市场化解法
3. **内容正确性**：K9 错误知识危害大 → 试点期树骨架用课标对齐的种子数据，个人内容标注「未经审核」
4. **未成年人**：不采集实名、不做真实支付、内容合规
5. **数据边界**：个人数据本地优先与森林共享之间的切换必须显式、可撤销

### 决策清单（待拍板，含建议）

> 每项：问题 → 建议 → 理由。拍板后把「建议」改为「已定」。

- **Q1（已定）**：**只保留 L1 自证**——点亮 = 发说说式的社交声明，学习完全自驱；机证 / 他证降级为可选插件（4.1）
- **Q2（已定）**：**未蒙尘的点亮者一人一票**——蒙尘窗口内未复点即失去投票资格（4.4）；公网期再评估二次方 / 贡献加权
- **Q3** 收费节点试点期要不要做「申请解锁」模拟？→ **建议：做，纯模拟（申请→批准，无真实支付）**。理由：成本极低，验证付费意愿与门控体验；K9 未成年人红线下不做真实支付（4.5）
- **Q4** 爬行进度默认公开还是私密？→ **建议：默认公开 + 可匿名 + 可关闭**（4.7 已写默认公开，此处确认）。理由：进度是森林养料（4.11 自治可见、4.14 隐形课堂），匿名保护个体，关闭权尊重隐私
- **Q5** K9 种子数据来源？→ **建议：课标知识点 + K12-KGraph 自动生成骨架，人工修正逻辑序**。理由：内容权威（课标）、自动化可行（KGraph）、人工保自然脉络（3.3/3.4）；标注「课标对齐/社区贡献」双轨
- **Q6（已定）**：创新不是节点属性，而是「给节点贡献第二份教程（新方法）」；教程默认折叠是系统行为（见 4.8）
- **Q7（已定）**：默认折叠先尝试；作者可对原创方法另设门控（4.9）
- **Q8（已定）**：新方法「同侪点赞达阈值」自动收录（「方法能用」由黄线复现把关，见 4.10）；投票只留给争议（4.8）
- **Q9** 实例/原理关系从哪来？→ **建议：K9 数学由课标/教材直接提供映射起步 + 社区作者声明新增；自动推断后置**。理由：现成且权威；自动推断需要数据积累，现在没有
- **Q10** 5–15 分钟是建议还是硬约束？→ **建议：建议 + 数据信号**（超长允许建，普遍超时触发拆分提案）。理由：符合「结构让错的活不下去」（4.11/4.12），不靠禁令靠数据；硬约束会误伤合理大节点
- **Q11** 自然脉络种子树由谁重建？→ **建议：自动生成 + 人工修正（数学），其他学科后置**。理由：K12-KGraph 现成（10.1）；专家纯手工成本高；人工修正保逻辑序
- **Q12** 商家挂载规则？→ **建议：两级**——商家自由挂自己点亮/持有的节点；挂别人节点需作者同意，佣金分成给节点持有者/方法作者（试点期先记账不分账）。理由：自由挂自己节点保低门槛；挂别人需同意防骚扰；分成激励作者（4.15）
- **Q13（已定）**：数据共享全部默认关闭（opt-in），包括 L1；K9 强制只 L1 + 监护人同意（4.16）
- **Q14** 跨终端同步优先级？→ **建议：E2E 加密同步优先（服务端零知识），局域网/自托管可选；试点期先手动 JSON**。理由：体验与隐私兼得（4.7）；局域网门槛高
- **Q15** 试点期要不要预留联邦标识？→ **建议：预留**——数据模型已用全局 ID + 内容寻址（5.2），顺路带联邦标识，零额外成本。理由：改 schema 便宜、改协议贵
- **Q16** MCP 粒度？→ **建议：一树一 server + 个人事件域与知识树域拆两个 server**。理由：连接数可控；事件域私有本地、树域可联邦，拆开职责清晰（5.3）
- **Q17** 机构提成比例要不要设上限？→ **建议：规范设上限（≤10%）+ 强制公开透明，上限内自由竞争**。理由：自治不是无规则（5.7）；上限防乱收费，透明是自治地基
- **Q18** 跨树搜索方式？→ **建议：试点期纯链接涌现（沿邻树查）+ 预留索引接口；注册表后置**。理由：注册表是新中心点，与无集群精神相悖（5.8）
- **Q19** 同步冲突合并策略？→ **建议：追加式数据零冲突（事件/点亮）；可编辑草稿用「版本分叉 + 显式选择」而非 LWW**。理由：LWW 静默丢数据；内容寻址下分叉天然，显式选择不丢数据（5.9）

**本批拍板（v0.2 修订，已写入正文）**：

- 提交教程 = 随意提交的日常动作，不标榜创新；**上传教程必须首次点亮**（4.8）
- 前置 = **推荐非强制**；跳关不推荐但支持，跳关成功 = 新路径；树序由使用大数据涌现（4.12）
- 分裂 = 时长拆分（1h → 4×15min）；合并 = 同目标（教程有差异）+ 点亮者限时投票（4.3）
- K9 内容**免费**；个人收入也抽 0.5% 佣金；收费 = 特殊案例解题思路等增值（4.15）
- 定位：先作为**爬塔游戏**，不对标 K9 宣传（1.4）
- **本地点亮**：只用教程不上传（4.7）
- 人防 > 系统防：点亮/教程可举报，**怎么刷上来怎么刷下去**；点亮多者优先推荐（4.10）
- **举报 = issue 机制**（公开/可关闭/信誉加权）；悬赏 = bounty issue；issue = 森林的问题层（4.10）
- **维护模型**：个人节点个人维护，群体节点点亮者维护；蒙尘成本催生**节点维护者职业**（4.19）
- **人治不是系统治**：无系统级验收，用户自己知道做到了；教程底线「可用别太烂」（4.19）
- **issue 分级**：绿线（需展开）/ 黄线（**无法复现 = 人治版机证**，多次黄线沉底）/ 红线（违法，**不公开 + 内部审核 + 每账号限 3 次**）（4.10 / 4.20）

- **Q20（已定）**：合并归属——个人节点并入群体节点后**降格为其中的一个付费教程**（保留作者权 + 收入权）；**必须个人自愿，不设强制合并**；群体 → 个人不允许（防掠夺）。拆分——教程作者可认领自己的教程成为个人节点（4.3）

## 10. 调研借鉴与来源

> 三路并行调研：A 知识树结构与掌握度 / B 所有权·治理·变现 / C 实践证据与打卡闭环。以下为与设计直接相关的发现与出处。

### 10.1 知识树结构与掌握度（A 路）

**Khan Academy 掌握度系统**
- 组织：课程（Course）→ 单元（Unit）→ 技能（Skill），技能间用前置依赖（prerequisite）串成图；未掌握前置时后续练习不可用或提示复习
- 分级：Attempted（尝试过）→ Familiar（熟悉）→ Proficient（熟练）→ Mastered（掌握）；升级依据「连续答对 + 单元测验 + Mastery Challenge」，答错回落
- 遗忘衰减：2018 年起久未练习的技能会掉级，倒逼间隔复习；官方建议用「熟练」而非「掌握」作为产出目标
- 来源：[Mastery levels 官方说明](https://support.khanacademy.org/hc/tr/articles/5548760867853-How-do-Khan-Academy-s-Mastery-levels-work)、[2018 机制更新](https://support.khanacademy.org/hc/en-us/community/posts/360023249611-Update-Mastery-Mechanics-Changes-September-2018)、[skills to proficient 官方博客](https://blog.khanacademy.org/why-khan-academy-will-be-using-skills-to-proficient-to-measure-learning-outcomes/)

**Duolingo 技能树**
- 旧版：技能树按行排布，行间解锁制（完成上一行才解锁下一行），每 5–6 个技能设检查点（Checkpoint），须通过复习测试继续；技能带皇冠等级 Crown 1–5，传说级（Legendary）要求零失误
- 2022 改版：线性路径 + 单元「指南书 + 课程节点」，单元末尾升级测试
- 验证机制：完成一组练习（约 10 题）错误不超限；红心生命值机制
- 来源：[Crown 机制](https://duolingo.fandom.com/wiki/Crown)、[2022 改版官方博客](https://blog.duolingo.com/new-duolingo-home-screen-design/)

**国内 K12 知识图谱**
- 国家中小学智慧教育平台：学科 → 学段 → 年级 → 册次（教材版本）→ 单元 → 课时，每课时挂微课 + 学习任务单 + 课后练习；是资源目录树，无知识点粒度的前置依赖
- 商业产品（洋葱学园 / 猿辅导 / 作业帮 / 学而思）：教材目录 → 章节 → 考点映射进智能题库，「诊断—推荐—测评」闭环；前置依赖图多为内部资产不公开
- 公开研究：K12-KGraph 构建了课程对齐的中国 K12 知识图谱（知识点带前置关系）；期刊有手工构建初中数学章节前置依赖图的论文
- 来源：[K12-KGraph 论文](https://ar5iv.labs.arxiv.org/html/2605.09635)、[K12-KGraph 代码库](https://github.com/haolpku/K12-KGraph)、[国家中小学智慧教育平台](https://baijiahao.baidu.com/s?id=1737204151700598490)

**错题即证据**
- 猿题库 / 作业帮模式：题目标注「教材-章节-考点」，练习自动批改，错题按知识点归因，再按「同知识点 + 前置知识点」推相似题；用正确率、连续答对、间隔复习判定「攻克」
- 学界「基于知识图谱的学习路径推荐」已被验证，但证据链普遍只覆盖做题，很少纳入实验 / 作品类证据
- 来源：[猿题库](https://baike.baidu.com/item/%e7%8c%bf%e9%a2%98%e5%ba%93/0)、[学习路径推荐研究](https://d.wanfangdata.com.cn/thesis/D03157712)

### 10.2 所有权 / 治理 / 变现（B 路）

**GitHub 分层授权五件套 → 知识节点**
- fork（分叉）= 节点分裂；PR + code review（保护分支强制必需评审）= 提案 + 评审；branch protection = 群体持有节点的写保护；license = 节点许可证；transfer 到组织 = 个人持有 → 群体持有的正规交接
- 来源：[Collaborative development models](https://docs.github.com/en/enterprise-server@3.15/pull-requests/collaborating-with-pull-requests/getting-started/about-collaborative-development-models)、[Transferring a repository](https://docs.github.com/en/enterprise-server@3.8/repositories/creating-and-managing-repositories/transferring-a-repository)、[Branch protection rules](https://ones.com/blog/required-approvals-on-github-how-branch-protection-rules-work/)

**Wikipedia 共识治理**
- 任何人可编辑，但改动须体现共识；争议解决阶梯：讨论页协商 → 第三方意见 → 调解 → 仲裁委员会
- 保护级别分层（半保护 / 扩展确认 / 全保护 / 待审编辑）→ 正好映射「点亮者才有修改 / 投票权」的权限梯度
- 词条合并流程：讨论页论证 → 合并 → 历史完整保留 + 原词条重定向
- 来源：[Consensus required](https://en.m.wikipedia.org/wiki/Wikipedia:Consensus_required)、[Protection policy](https://en.wikipedia.org/wiki/Wikipedia:Protection_policy)、[Administrators](https://en.wikipedia.org/wiki/Wikipedia:Administrators)、[Articles for merging](https://en.wikipedia.org/wiki/Wikipedia:Articles_for_merging)

**DAO 投票**
- Snapshot：链下签名投票（零 gas 费）；Aragon：链上 token voting，可配支持率阈值、最低参与率、投票时长
- 二次方投票：投 n 票成本 n²，防多数暴政；但无可靠身份层时怕女巫攻击
- 防女巫：Gitcoin Passport / Human Passport × Snapshot，为每个真实人发放一票（一人一票而非一账号一票）
- 来源：[Aragon Token Voting](https://docs.aragon.org/token-voting/1.x)、[Quadratic voting 指南](https://app.gitcoin.co/blog/quadratic-voting-a-how-to-guide)、[Quadratic voting](https://en.wikipedia.org/wiki/Quadratic_voting)、[Human Passport × Snapshot](https://passport.human.tech/blog/human-passport-x-snapshot-making-dao-coordination-more-secure)

**知识付费**
- 知乎盐选：作者稿费约千字 30–100 元、分成约 50%；小报童：订阅制 + 合伙人分佣；爱发电：会员制打赏；Patreon / GitHub Sponsors：订阅赞助
- open core（GitLab）：核心内容开源免费，增值层（托管 / 企业版 / 高级功能）收费
- 来源：[小报童合伙人计划](https://help.xiaobot.net/partner.html)、[爱发电创作者 FAQ](https://guide.afdian.com/faq/faq-for-creators.md)、[GitHub Sponsors](https://docs.github.com/en/sponsors/sponsoring-open-source-contributors/about-sponsorships-fees-and-taxes)、[GitLab Stewardship](https://handbook.gitlab.com/handbook/company/stewardship/)

**分裂 / 合并先例**
- LibreOffice vs OpenOffice（2010）：社区追随的是治理信任与活跃度而非代码本身；fork 是治理失效时的逃生阀；可持续的治理结构比一次性代码贡献更重要
- Wikipedia 合并：透明讨论 + 历史保留 + 明确正统维护方
- 来源：[A year after the fork](https://arstechnica.com/information-technology/2011/09/a-year-after-the-fork-libreoffice-still-going-strong/)、[Fork 与社区可持续性](https://www.sciencedirect.com/science/article/pii/S0164121213002744)、[Wikipedia:Merging](https://en.wikipedia.org/wiki/Wikipedia:Merging)

### 10.3 实践证据与打卡闭环（C 路）

**「真的学会了」的验证**
- Coursera：计分作业及格 + 专项课程 capstone 毕业设计才发证；edX：在线监考（身份核验 + 屏幕录制 + 浏览器锁定）——「做过」是发证的必要条件
- OJ 自动判题（LeetCode / 洛谷）：编译 + 多组测试数据 + 时间/内存限制，结果客观可复现——「实践即证据」的最强形态
- 研究证实「看完视频」与成绩相关性弱 → 证书绑定计分作业而非观看
- 来源：[Coursera Specializations FAQ](https://blog.coursera.org/got-a-question-on-specializations-we-have/)、[洛谷评测机制](https://help.luogu.com.cn/manual/luogu/problem/judging)、[MOOC 点击流与成绩](https://ar5iv.labs.arxiv.org/html/1503.06489)

**证据型认证**
- Open Badges 2.0：BadgeClass（标准 + criteria）+ Assertion（谁在何时因何获得）+ evidence 字段（链接到作品 / 测试记录 / 项目 URL）；可烘焙进 PNG 或托管 URL，任何人可反向验证真伪
- 微证书（micro-credentials）：基于证据的能力凭证，由领域专家审阅作品样本（performance-based），比「听够课时」更有说服力
- 来源：[Open Badges 2.0](https://www.imsglobal.org/sites/default/files/Badges/OBv2p0Final/history/2.0.html)、[Digital Promise 微证书与开放徽章](https://digitalpromise.org/2019/05/21/microcredentials-open-badges/)

**打卡与监督**
- Forest 专注森林：离开 App 树就枯萎的真实代价 + 专注时长可兑换真实种树；小打卡：公开打卡日记 + 点赞评论，靠社交可见性维持真实
- 自证不可防伪，行业用他证补强：群报数（照片 / 定位 / 群主审核）、见证打卡团（押金 + 奖惩）
- 警惕过度依赖拍照自证（加班拍照打卡被判定为假）→ 证据应分级而非一刀切
- 来源：[Forest](https://en.wikipedia.org/?curid=66877454)、[小打卡](http://media.qimingpian.cn/weixin/3a7affab772a93975327839916d1841d.html)、[工人日报：拍照打卡证明加班被判假](https://www.workercn.cn/c/2024-05-31/8273942.shtml)

**习惯反馈闭环**
- GTD 软件化（日事清「收集-整理-执行-复盘」）；每日复盘 App 把「计划-总结-反思」固化成模板（PDCA 轻量实现）
- Notion 学习模板：数据库把总目标拆成每日任务自动追踪；滴答清单：习惯打卡 + 连续天数（streaks）+ 统计曲线，用数据反馈激励持续执行
- 来源：[日事清](https://www.onlinedown.net/soft/1153313.htm)、[ClickUp 习惯追踪对比](https://clickup.com/learn/topic/productivity/tools/features/habit-tracking/)

**爬树体验**
- roadmap.sh：技能树 / 路线图节点可勾选，进度百分比持久化——最接近「爬树」的成熟产品
- Coursera Specialization：课程序列化 + 进度条 + 终点 capstone，形成「起点 → 进度 → 毕业」完整旅程
- Obsidian graph view「好看不好用」，需配合语义与学习路径才有价值
- 来源：[roadmap.sh](https://roadmap.codex-soft.net/about/)、[少数派：图谱应该怎么用](https://sspai.com/post/112973)

### 10.4 三路调研的共识（已进设计）

1. 点亮绑定「实践产物」而非「看完」（C1 / A3）
2. 掌握度分级 + 遗忘衰减，不一次性点亮（A1）
3. 权限分梯度，重大修改须共识投票，争议升级仲裁（B2）
4. 变现走 open core：正文开源 + 增值收费（B4）
5. 分裂 / 合并规则在社区形成前定好（B5）
6. 错题 / 卡点即证据，回传改进教程（A5 / C3）
