# humansneeds.com 整站需求与开发计划

平台从用户想要什么出发。用户可以记下买不起的商品、可接受的预算和实际用途，也可以描述尚无现成商品的问题。教程、替代方案、商家报价和实际成交都能回到原需求。

## 本次发布

- 首页提供「记录我想要的东西」和需求图谱入口，继续提供点亮、知识平台、工具和反馈。
- 「我的想要」复用现有账号。需求支持新建、编辑、删除和标记已解决，预算及商品链接可留空。所有记录均为私人数据。
- 展开的教程可以发起需求记录，携带教程名称和标识。当前线上教程数据还没有可用的版本快照。需求记录与账号原有习惯状态独立存放。
- 生产路由沿用主站代理规则。页面为 `/wants/`，私人 API 为 `/api/state/wants`，账号文件位于 `DATA_DIR/wants/`，随主站数据一并备份。

## 整站后续交付

1. **公开需求图谱。** 用户主动选择加入或发布，可随时撤回。保留用途、规格、价格上限、等待时间、是否接受二手等差异。相似需求建议由用户选择，运营能拆分和合并。想要、条件购买意向、订单、履约和其他解决方式分别计数。保留现有 INeedThis 入口和历史数据。
2. **教程双向联动。** 需求页能找选购、替代、自制和使用教程，教程步骤能发起需求。关联保留节点、教程版本、步骤和材料规格，历史实践指向当时版本。点亮保留多级导航、唯一活动计时、子任务、笔记、习惯、历史、点亮草稿和显式自证。知识共创保留版本、权限、撤回、节点归属和治理机制。
3. **供给与交易。** 商家按需求给出规格、总价、有效期、交付和售后条件。首个类目贯通报价、下单、付款、履约、取消、退款及争议。下单后固定报价快照，重复回执幂等处理。实际复用 `/order` 前核对其支付、数据与售后边界。团购和预售另设成团及退款状态。
4. **广告及随机发放。** 明确标识广告，广告与需求、教程、报价排序分开。广告收入、交易收入、赞赏和教程外链佣金分别记账。奖池使用已对账收入，参与资格与名单开奖前固定。抽取结果可核验，重试复用同一期结果。对外展示奖池和发放汇总，个人结果使用脱敏标识。发放比例、周期、资格、中奖人数、领取与失败处理规则经确认，按首发市场核对后再接真实资金。
5. **长期机制。** 保留免费使用、自愿赞赏、教程外链佣金及节点持有者收益设计。需求贡献回报、站内交易费率与广告奖池分别确认。继续推进路径、机证、治理、桌面悬浮及 Android。

## 验收

- 账号 A 创建一件暂时买不起的东西，刷新后仍可编辑，账号 B 及未登录访客无法读取。教程入口带入来源，保存失败可重试。
- 公开图谱接通后验证公开授权、撤回和统计更新。交易接通后验证报价、履约、退款与售后。最终用例从私人需求经过教程、方案、报价、交易或替代实践，回到需求解决结果。
- 真实广告发放前演练一期收入对账、名单冻结、可核验抽取、幂等重试及发放对账。
